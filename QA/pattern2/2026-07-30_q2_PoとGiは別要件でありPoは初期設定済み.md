# Task 1.2 表のPo行とGi行は別要件（PoはSW110の解答に出てこない理由の続き）

## 質問

問題文にはpoに設定してと書いているのに
HQ    2001    SW110    Po1、Po2
SWではgiに設定しているのはなぜ？

## 回答

問題文の表には元々「Po」と「Gi」の2種類の別々の行がある。

```
| HQ | 2000 | SW110 | Po1、Po2 | あり（タグ付き） |
| HQ | 2000 | SW110 | Gi0/0    | なし（タグなし） |
...
| HQ | 2001 | SW110 | Po1、Po2 | あり（タグ付き） |
| HQ | 2001 | SW110 | Gi0/1    | なし（タグなし） |
```

SW110には「Po1/Po2」と「Gi0/0・Gi0/1」という別々のポートに対する別々の要件が存在する。同じ要件の言い換えではなく独立した2つの要件。

### Po1・Po2（トランク・タグ付き）の役割

SW110からSW101・SW102（コア側）へのアップリンク。1本の物理リンク（EtherChannel）でVLAN2000とVLAN2001の両方をタグ付きで多重化して流す必要があるため、トランクポート（Po）として設定する。

### Gi0/0・Gi0/1（アクセス・タグなし）の役割

Po1/Po2とは別の物理ポートで、SW110配下のエンドホスト・機器につながる末端ポート。1つのポートにつき1つのVLANしか使わず、接続先が802.1Qタグを理解しない機器（PC等）を想定しているため、タグなし（アクセスポート）で設定する。Gi0/0はVLAN2000専用、Gi0/1はVLAN2001専用とポートごとに担当VLANが分かれている。

### なぜ解答configにPoの設定が出てこないのか

前回のQ&A（[Task 1.2 SW101が解答に出てこない理由](2026-07-30_q2_SW101とSW110のVLAN設定が空白の理由.md)）で確認した通り、SW110の初期コンフィグ（`EI_v2.yaml`）で既にPo1・Po2ともにメンバーポートが割り当て済み・トランクモード・VLAN許可制限なし（デフォルト全VLAN許可）になっているため、Po1/Po2に対しては追加コマンドが不要（要件を初期状態で既に満たしている）。

一方、Gi0/0・Gi0/1は初期コンフィグに一切登場しない、まっさらな状態のポートなので、こちらは新規に明示的な設定が必要だった。だから解答configには以下のGiの設定だけが出てくる:

```
interface GigabitEthernet0/0
switchport
switchport mode access
switchport access vlan 2000

interface GigabitEthernet0/1
switchport
switchport mode access
switchport access vlan 2001
```

「Poの代わりにGiを設定している」のではなく、「Poの要件はもう満たされているので書く必要がなく、Giの要件だけが新規作業として残っていた」という状態。
