# Task 1.8 `route-target export 10000:1` はどこに設定するのか / 値 10000:1 の根拠

## 質問

route-target export 10000:1 といきなり出てくるけどこれは R1 に設定している？
何を根拠にこの 1:10000 を出している？

## 回答

### 1. R1 には設定しない（R1 は VRF を持たない P ルータ）

`route-target` は独立したグローバルコマンドではなく、**`vrf definition` のサブコマンド**です。

```
vrf definition fabd2          ← このブロックの中でしか書けない
 rd 10000:3
 route-target export 10000:1  ← ここ
 route-target import 10000:1
 !
 address-family ipv4
```

したがって設定先は **VRF `fabd2` を持つ PE = R3 / R4 / R5 / R6 の 4 台だけ**です。

EI_v2.yaml で R1 / R2 の初期コンフィグを検索すると、`vrf` / `route-target` /
`router bgp` のいずれも **1 行もヒットしません**（あるのは `router ospf 1` のみ）。

```
R1: vrf|route-target|router bgp のヒット数 = 0
R2: vrf|route-target|router bgp のヒット数 = 0
```

これは設計上も必然です。R1/R2 は **P（プロバイダコア）ルータ**で、役割は
「ラベルを見て次のラベルに貼り替えて転送する」だけ。VPN 経路（VPNv4）も
顧客の IPv4 経路も一切保持しません（**BGP-free core**）。VRF を持たせる＝
顧客経路をコアに持ち込むことになり、L3VPN でコアをスケールさせる目的そのものが崩れます。

| 機器 | 役割 | VRF | BGP | RT |
|---|---|---|---|---|
| R1 / R2 | **P**（コア） | なし | なし | **なし** |
| R3〜R6 | **PE**（エッジ） | fabd2 | AS 10000 | **10000:1** |

Task 1.7（MPLS アンダーレイ）で R1/R2 に入れたのは OSPF + LDP だけ、というのと
きれいに対応しています。

### 2. `10000:1` という値の根拠

3 段階に分けて考えると納得できます。

#### (a) フォーマットとしての意味

RT は `ASN:nn` 形式の**拡張コミュニティ**（32bit AS + 16bit の任意番号）。

- `10000` = **この SP の AS 番号**。Task 1.8 の `router bgp 10000` と同じ数字。
- `:1` = SP が運用する **VPN の通し番号 #1**（この場合 fabd2）。

→ `10000:1` = 「**AS10000 が運用する VPN #1**」という意味のタグ。

数字そのものに技術的な必然性はなく、**運用者が決める任意の識別子**です。
証拠として、同じ EI_v2.yaml の中で SD-WAN の cEdge21/cEdge22 は
まったく別の値を使っています。

```
cEdge21 / cEdge22:
vrf definition 999
 rd 1:999
  route-target export 1:999
  route-target import 1:999
```

（EI_v2.yaml 1854/1855 行、1960/1961 行）

つまり「1:999 でも 10000:1 でもよい。VPN ごとに決めた値を全 PE で揃える」のが本質です。

#### (b) このラボで `10000:1` が正解になる直接の根拠

**R5 と R6 の初期コンフィグに、既に `route-target export/import 10000:1` が
入っているから**です。

EI_v2.yaml の `rd` / `route-target` を全部拾うとこうなります。

| 行 | 機器 | RD | RT export/import |
|---|---|---|---|
| — | **R3** | **（VRF 自体が無い）** | **—** |
| 2758-2760 | R4 | 10000:4 | **10000:4** ← 孤立 |
| 2894-2896 | **R5** | 10000:5 | **10000:1** ← 既存値 |
| 3028-3030 | **R6** | 10000:6 | **10000:1** ← 既存値 |
| 1854-1855 | cEdge21 | 1:999 | 1:999（別 VPN） |
| 1960-1961 | cEdge22 | 1:999 | 1:999（別 VPN） |

`10000:1` は**新規に発明した値ではなく、fabd2 VPN で既に稼働している現行値**。
Task 1.8 がやっているのは、

1. **R3**: VRF ごと存在しないので、既存値 10000:1 で新規作成
2. **R4**: 自分だけ 10000:4 を使っていて VPN から孤立 → `no route-target both 10000:4`
   で外し、10000:1 に合流

という「**既存の多数派に合わせる**」作業です。理屈の上では逆向き（4 台全部を
10000:4 に統一）でも VPN は成立しますが、変更が 3 台に増えるので最小変更になりません。

なお `Questions/pattern2/pattern2_q8.md` が空（0 byte）のため、実際の問題文で
RT 値が明示指定されていたかは確認できません。本番の試験では
「RT は 10000:1 を使用すること」と問題文で与えられるのが通例です。

#### (c) 設計上の必然 — なぜ「揃える」必要があるか

RT は「**この VPN 経路を誰が受け取ってよいか**」を示す配送ラベルです。

- PE が VRF の経路を VPNv4 に載せるとき、`export` の RT を付けて広告する
- 受け取った PE は、自分の `import` RT と一致する経路だけを VRF に入れる

全 PE が `export 10000:1` / `import 10000:1` で揃うと、
**どの PE の経路も他の全 PE がインポートする＝フルメッシュ VPN** になります。
（ハブ&スポークにしたい場合は、ここで export/import を非対称にする）

### 3. RD と RT を混同しない（この問題の一番の勘所）

同じ `10000:x` 形式なので紛らわしいですが、まったく別物です。

| | この問題での値 | 範囲 | 役割 |
|---|---|---|---|
| **RD**<br>(Route Distinguisher) | R3=**10000:3**<br>R4=10000:4 / R5=:5 / R6=:6 | **PE ごとに一意** | IPv4 プレフィックスの前に付けて **VPNv4（12 バイト）として一意化**するだけ。<br>顧客間でアドレスが重複しても区別できるようにする。<br>**経路配布の制御には一切使わない** |
| **RT**<br>(Route Target) | 全 PE **10000:1** | **VPN 全体で共通** | どの VRF にインポート/エクスポートするかを決める。<br>**VPN のトポロジ（フルメッシュ / ハブ&スポーク）を決定する** |

だから R3 の config が

```
 rd 10000:3            ← 自分の番号（一意）
 route-target export 10000:1   ← VPN 共通の番号
 route-target import 10000:1
```

という**一見アンバランスな組み合わせで正しい**わけです。
「RD も RT も 10000:3 に揃える」「RT を PE 番号にする」は典型的な誤答パターンです。

### 4. 揃えないとどうなるか（トラブルシュートの見え方）

RT が不一致でも **BGP セッションは全部 Established になります**。ネイバー確立に
RT は無関係だからです。症状は経路の欠落としてだけ現れます。

- `show bgp all summary` → **5 本とも Established。異常なし**に見える
- `show bgp vpnv4 unicast all` → 経路は届いている（RIB-in にはある）
- `show ip route vrf fabd2` → **他拠点の経路が入っていない**

R4 が 10000:4 のままだと、R4 が広告した経路は誰もインポートせず、
R4 も他 PE の経路をインポートしない = R4 だけ VPN から孤立します。
「セッションは上がっているのに疎通しない」ため切り分けが難しい、典型的な減点箇所です。

確認は `show vrf detail fabd2` で import/export RT を全 PE で見比べるのが最短。

```
R3# show vrf detail fabd2
VRF fabd2 (VRF Id = 1); default RD 10000:3
  Export VPN route-target communities
    RT:10000:1
  Import VPN route-target communities
    RT:10000:1
```
