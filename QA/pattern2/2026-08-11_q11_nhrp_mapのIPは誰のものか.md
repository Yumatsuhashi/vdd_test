# Task 1.11 `ip nhrp map` で対応づけている IP は誰のものか（＝ハブ R24 の「2 つの顔」）

## 質問

nhrp mapで対応づけているIPはどこのものかわかる？

## 回答

### 結論：どちらもハブ R24 のもの

```
ip nhrp map 10.200.0.1 200.99.24.2
             ↑            ↑
      R24 の Tunnel0    R24 の Gi1
     （トンネル内の住所） （インターネット上の住所）
```

NHRP map は「同じ 1 台が持つ 2 つの顔」を結びつける行。
`ip nhrp nhs 10.200.0.1` の `10.200.0.1` と map の第 1 引数は同じ物で、
「NHS はトンネル上の `10.200.0.1` に居る。そいつに実際に届けるには
インターネット上の `200.99.24.2` に GRE を投げろ」と教えている。

### 出てくる IP の正体（EI_v2.yaml で確認済み）

| IP | 誰の何 | 層 |
|---|---|---|
| **10.200.0.1** | **R24 の Tunnel0** | オーバーレイ（protocol address）＝ NHS |
| **200.99.24.2** | **R24 の GigabitEthernet1** | アンダーレイ（NBMA）＝新しい宛先 |
| 10.2.255.24 | R24 の Loopback0 | **旧** NBMA（初期設計の名残） |
| 10.200.0.61 | R61 の Tunnel0 | オーバーレイ（自分の顔） |
| 10.200.0.70 | R70 の Tunnel0 | オーバーレイ（自分の顔） |
| 200.99.61.2 | R61 の Gi0/4 | 自分の NBMA（＝新 `tunnel source`） |
| 200.99.70.2 | R70 の Gi0/1 | 自分の NBMA（＝新 `tunnel source`） |

トンネル内サブネットは `10.200.0.0/24`（ハブ .1 / R61 .61 / R70 .70）。

### 初期コンフィグ → 解答で何が変わったか

R61 / R70 の初期 Tunnel0（EI_v2.yaml）:

```
interface Tunnel0
 ip address 10.200.0.61 255.255.255.0
 ip nhrp map multicast 10.2.255.24        ← NBMA = R24 の Lo0
 ip nhrp map 10.2.255.24 10.200.0.1
 ip nhrp network-id 1010
 ip nhrp nhs 10.200.0.1
 tunnel source Loopback0                  ← 自分側も Lo0
 tunnel mode gre multipoint
 tunnel protection ipsec profile prof
```

**初期設計は「NBMA = 両端の Loopback0」**（アンダーレイは MPLS 側でグローバル）。
問題文の「ハブとスポーク間でDMVPNを確立する際に、ループバックインターフェイスの
IPアドレスを使用しないこと」がこれを禁じるので、NBMA を物理 I/F の公開 IP に総取っ替えする。

| | 旧（Loopback ベース） | 新（インターネットベース） |
|---|---|---|
| 自分の NBMA | `tunnel source Loopback0` | `tunnel source Gi0/4`（200.99.61.2）/ `Gi0/1`（200.99.70.2） |
| ハブの NBMA | 10.2.255.24 | **200.99.24.2** |
| 引くテーブル | グローバル | **VRF WAN**（`tunnel vrf WAN`） |

新 NBMA は VRF WAN 経由でしか届かない。旧 `10.2.255.24` は VRF WAN のテーブルに存在しない
（＝インターネットからは絶対に届かない）ので、この付け替えは必須。

### ⚠️ 初期コンフィグの map は引数の順序が逆

構文は `ip nhrp map <オーバーレイのIP> <NBMAのIP>`。ところが初期行は:

```
ip nhrp map 10.2.255.24 10.200.0.1
            └ Lo0(NBMA) └ Tunnel0(オーバーレイ)   ← 逆
```

正しくは `ip nhrp map 10.200.0.1 10.2.255.24` であるべき。
同じブロックの `ip nhrp map multicast 10.2.255.24`（こちらは NBMA を取る構文なので正しい）とも矛盾している。

**解答の `ip nhrp map 10.200.0.1 200.99.24.2` は、宛先の付け替えと同時にこの順序も直している。**
消す行（`no ip nhrp map 10.2.255.24 10.200.0.1`）と入れる行で引数の並びが違うのはそのためで、タイプミスではない。

### `10.2.255.24` は役割が変わる（外側 → 中身）

同じ `10.2.255.24` が、このタスクの中で外側から中身へ引っ越す。

- **Before**: トンネルを張るための NBMA（＝外側の封筒の宛先）
- **After**: NBMA からは降板。代わりに**トンネルの中を EIGRP で広報される経路**になる

問題文の広報対象 3 本のうちの 1 本がこれ（問題文の `10.255.5.24/32` は `10.2.255.24/32` の誤記）。

### ハブ R24 側に map が 1 行も無い理由

R24 の初期 Tunnel0 は `ip nhrp network-id 1010` だけで `ip nhrp map` が無い。
**ハブは相手の NBMA を知らなくてよい**から。スポークが `ip nhrp nhs` を頼りに自分から
登録しに来るので、ハブはその登録内容を動的に覚える。

解答でハブに足すのは `ip nhrp map multicast dynamic` の 1 行だけ。
「登録してきたスポーク全員にマルチキャスト（＝EIGRP Hello）を複製しろ」という意味で、
**相手が増減しても書き換え不要**にするための行。
スポーク側が `ip nhrp map multicast 200.99.24.2` と手書きなのは、相手（ハブ）が 1 台に固定されているから。

### 補足：R24 の初期 `tunnel source Ethernet0/3` は存在しない I/F

R24 の物理 I/F は Gi1〜Gi4 のみ（links も `R24-GigabitEthernet1<->SP_1-Ethernet0/1` 等）。
初期の `tunnel source Ethernet0/3` は実体の無い指定なので、問題文がわざわざ
「R24は、IPsecピアとの接続に GigabitEthernet1 を使用すること」と名指ししている。

### まとめ図

```
        オーバーレイ（トンネルの中 10.200.0.0/24）
   R61 .61 ───────────── NHS 10.200.0.1 ───────────── R70 .70
      │                        │                        │
      │   ip nhrp map 10.200.0.1 200.99.24.2            │
      │   （この 1 行が上下をつなぐ）                    │
      ↓                        ↓                        ↓
   200.99.61.2 ──── SP_1(AS19999) ──── 200.99.24.2 ──── 200.99.70.2
        アンダーレイ（VRF WAN / インターネット）
```
