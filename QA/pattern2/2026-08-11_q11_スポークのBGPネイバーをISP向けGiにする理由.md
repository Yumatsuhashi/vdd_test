# Task 1.11 スポークの BGP neighbor を「ハブ側の Gi」の対向にする理由（＝ISP とのアンダーレイ BGP）

## 質問

spokeルーターでbgpののneighborをhubに繋がっているgigbit ethernetとしているけどこれはなぜ必要？

## 回答

### 前提の訂正：その Gi は「ハブに繋がっている」のではなく「ISP に繋がっている」

```
R61 Gi0/4 200.99.61.2 ──── SP_1 Eth0/3 200.99.61.1   ← BGP neighbor はここ
                             (AS 19999 = インターネット)
R24 Gi1  200.99.24.2 ──── SP_1 Eth0/1 200.99.24.1
R70 Gi0/1 200.99.70.2 ─── SP_1 Eth1/0 200.99.70.1
```

ハブ R24 とスポークは**直接繋がっていない**。間に ISP（CML ノード `SP_1`、AS 19999）が 1 台挟まる。
だから「ハブへの道を教えてもらう相手」として ISP と BGP を張る。

### なぜ必要か — 3 段構え

#### ① VRF WAN のルーティングテーブルが空だから

`Tunnel0` には `tunnel vrf WAN` が入るので、**外側の GRE/IPsec ヘッダの宛先 `200.99.24.2`
（＝ハブ R24 の公開 IP）を VRF WAN のテーブルで引く**。
ところが VRF WAN の中身は connected の `200.99.61.0/30` だけ。`200.99.24.2` への経路が 1 本もない。

→ 再帰ルックアップ失敗 → `%TUN-5-RECURDOWN` でトンネルが上がらない
→ ISAKMP パケットすら飛ばない → **DMVPN 全滅**

#### ② その経路を供給できるのが SP_1 との BGP だけ

SP_1 の初期コンフィグ（`EI_v2.yaml`）:

```
router bgp 19999
 redistribute static
 neighbor 200.99.24.2 remote-as 65002     ← R24
 neighbor 200.99.61.2 remote-as 65006     ← R61 を待っている
 neighbor 200.99.62.2 remote-as 65006     ← R62（問題文で除外）
 neighbor 200.99.70.2 remote-as 65007     ← R70 を待っている
 default-information originate
!
ip route 0.0.0.0 0.0.0.0 Null0
```

この eBGP が上がって初めて VRF WAN に `0.0.0.0/0` が入り、`200.99.24.2` が引けるようになる。

#### ③ 問題文がそう要求している

> ブランチルータは、専用のVRFを使用してISPへ接続し、**BGP経由でデフォルトルートを受信**すること

`ip route vrf WAN 0.0.0.0 0.0.0.0 200.99.61.1` でも技術的には動くが、これは要件違反。

### なぜ「その物理 Gi の対向 IP」なのか（Loopback ではなく）

- **eBGP 直結は TTL 1**。`update-source` を弄らなければソース IP は出力 I/F の `200.99.61.2`。
  SP_1 側が `neighbor 200.99.61.2` と決め打ちしているので、ソース IP がズレるとセッションを拒否される
- Loopback ピアにするには双方に `ebgp-multihop` ＋ `update-source` ＋ 互いの Loopback への経路が必要。
  ISP はそんなものを持っていない
- そもそも **R61 の `Loopback0`（10.6.255.61）はグローバル所属**で、VRF WAN には Loopback が 1 本もない
  ＝選択肢として存在しない
- 問題文の「ループバックインターフェイスのIPアドレスを使用しないこと」とも一致
  （この要件は主に `tunnel source` の話だが、方向性は同じ）

### なぜ `address-family ipv4 vrf WAN` の下なのか

`200.99.61.1` は **VRF WAN のテーブルにしか存在しない**アドレス。
グローバル直下に書くと、同じ IP でも別人格の neighbor が無言で新規作成され Idle のまま放置される
（Task 1.10 の PE 側と同じ構図 → `QA/pattern2/2026-08-07_q10_PE側だけaddress-family_ipv4_vrf配下に打つ理由.md`）。

### 二層構造として整理

| 層 | プロトコル | テーブル | 運ぶもの |
|---|---|---|---|
| **アンダーレイ（外側の封筒）** | BGP（AS 19999 と） | VRF WAN | `0.0.0.0/0` だけ。**トンネルを立てるためだけ** |
| **オーバーレイ（中身）** | EIGRP AS 65006 | グローバル | 業務経路（`10.2.114.0/30` 等） |

**この BGP は業務経路を一切運ばない。**「ハブの公開 IP に届く足場」を作るためだけの配線。

なお R61 はグローバル直下にもう 1 本 BGP を持つ（`neighbor 100.5.61.1 remote-as 10000` ＝ R5 との
MPLS L3VPN 用）。これとは全く別物なので混同しないこと。

### R61 と R70 で作業量が違う

| | ISP 向け BGP neighbor | Task 1.11 での作業 |
|---|---|---|
| **R61** | 初期コンフィグに**既にある**（`af ipv4 vrf WAN / neighbor 200.99.61.1 remote-as 19999`） | 確認のみ（打ち直し不要） |
| **R70** | **無い**（あるのは DC 向け `neighbor 100.6.70.1 remote-as 10000`） | `interface Gi0/1` に `vrf forwarding WAN` ＋ `neighbor 200.99.70.1 remote-as 19999` を**新規入力** |

「なぜ必要か」が実作業として効いてくるのは **R70 側**。
R61 だけ見て「もう入ってるじゃん」と流すと R70 で落とす。

### 打たないとどうなる（症状）

```
show ip route vrf WAN            → connected の /30 のみ。デフォルトなし
show ip cef vrf WAN 200.99.24.2  → 引けない
Tunnel0                          → %TUN-5-RECURDOWN、line protocol down
show crypto isakmp sa            → 空（IKE がそもそも始まらない）
show dmvpn                       → NHS 未登録
```

### 検証コマンド

```
show ip bgp vpnv4 vrf WAN summary          ! 200.99.61.1 が Established・受信1本
show ip route vrf WAN 0.0.0.0              ! B* 0.0.0.0/0 via 200.99.61.1
show ip cef vrf WAN 200.99.24.2            ! ★ここが引けるか＝トンネルの生死
show dmvpn
show crypto isakmp sa
```
