# Task 1.12 `rotary 3` を入れる理由と、ポート番号 3003 の導出（3000+n）

## 質問

この問題でrotaryを入れているのはなぜですか　解説して

## 回答

### 一言でいうと

**`rotary 3` は「ルータに TCP 3003 番で待ち受けさせる」ための設定**。
ACL は来た接続を通すか落とすかを決めるだけで、**そもそも 3003 番で LISTEN していなければ接続は成立しない**。

### ポート番号 3003 の正体 —— `rotary 3` の「3」は逆算して決める

IOS の rotary グループは、グループ番号にオフセットを足したポートで待ち受ける。

| 接続方式 | ポート計算式 | `rotary 3` の場合 |
|---|---|---|
| **Telnet** | **3000 + グループ番号** | **3003** ← これ |
| Raw TCP | 5000 + グループ番号 | 5003 |
| Telnet binary | 7000 + グループ番号 | 7003 |

（個別 line を直接指定する場合は 2000+line / 4000+line / 6000+line。rotary グループは 3000/5000/7000 系列）

問題文が「**ポート3003のみ**で受け付けること」と指定 → `3003 − 3000 = 3` → **`rotary 3`**。

**数字の 3 に深い意味はなく、要求ポート番号から機械的に逆算した値**。
問題文が 3010 なら `rotary 10` になる。

### なぜ rotary という仕組みなのか（名前の由来）

本来 rotary は**リバース Telnet**（ターミナルサーバから配下機器のコンソールに入る用途）の機能。
「グループにまとめた複数の line のうち、**空いている line を順繰りに（rotary＝回転式に）割り当てる**」
ので この名前が付いている。

`line vty 0 15` に `rotary 3` を打つと **16 本の VTY が丸ごと 1 つのグループ**になり、
3003 番への接続が空いている VTY に自動で振り分けられる。

### 「なぜ rotary でなければならないか」——問題文が他の解法を封じている

ポート 3003 で Telnet を受ける方法は他にもあるが、問題文の最後の 1 行がそれを禁じている。

> この構成は、動作のために **NATへ依存しない**こと。

これは「**NAT で 3003 → 23 に変換して解決するな**」という意味。
R23 には Task 1.12 の前半で NAT を設定しているので、
`ip nat inside source static tcp ... 3003 ...` で変換すれば動いてしまう。
それを明示的に潰して「**VTY ライン自身の機能で解け**」と誘導している。その答えが `rotary`。

### rotary と ACL の役割分担（両方揃って初めて要件を満たす）

| 要件 | 担当 | 理由 |
|---|---|---|
| ポート **3003 で**受け付ける | **`rotary 3`** | VTY はデフォルトで **23 番しか LISTEN しない**。3003 番の口を開ける設定が必要 |
| ポート 3003 **のみ**（＝23 を拒否） | `access-class CCIETELNET in` | rotary を足しても **23 番は開いたまま**。塞ぐには ACL が要る |

```
rotary 3         → 口を開ける（listen）
access-class in  → 通す/落とすを決める（filter）
```

**ACL は開いていない口を開けられないし、rotary は開いた口を閉じられない。** 別々の仕事。

### 打たないとどうなるか

`rotary 3` を忘れて ACL だけ入れると:

```
R24# telnet 200.99.23.2 3003
Trying 200.99.23.2, 3003 ... % Connection refused by remote host   ← LISTEN していない

R24# telnet 200.99.23.2
Trying 200.99.23.2 ... % Connection refused by remote host          ← ACL の deny 23 で拒否
```

**23 番は ACL で塞がれ 3003 番は開いていない → Telnet で一切入れなくなる。**
ACL の `permit tcp any any eq 3003` は永久に空振りする行になる。

ラボで打つ順番は `rotary 3` → 疎通確認 → `access-class` が安全
（逆順だと一瞬自分を締め出す。コンソールがあるので復旧は可能）。

### 「すべての GigabitEthernet インターフェイス経由」も rotary が満たす

> R23は、有効になっているすべての GigabitEthernetインターフェイスを経由したTelnet接続を…

`rotary` は特定インターフェースに紐づかず、**ルータが持つ全 IP アドレスで 3003 番を LISTEN する**。
R23 の該当 I/F（Gi4 は IP 未設定なので対象外）:

| I/F | IP |
|---|---|
| Gi1 | 200.99.23.2（ISP 側） |
| Gi2 | 10.2.115.1 |
| Gi3 | 10.2.215.1 |

どれ宛でも `telnet <IP> 3003` で入れる。個別に I/F を指定する設定は不要。

### 検証コマンド

```
R23# show tcp brief all | include 3003        ! 3003 で LISTEN しているか
R23# show line                                ! VTY の一覧
R23# show run | section line vty

R24# telnet 200.99.23.2 3003                  ! ccieuser / CCIE!nfr4 で入れること
R24# telnet 200.99.23.2                       ! ★拒否されること（23 番）
```

### 補足

- `rotary 3` は **パターン1・2・3 すべて共通**（解答 HTML が `row-common`）。この 1 行はそのまま暗記でよい
- ⚠️ 解答 HTML のパスワードは `CC!E!nfr4`、問題文は `CCIE!nfr4`。実機では問題文を優先する
