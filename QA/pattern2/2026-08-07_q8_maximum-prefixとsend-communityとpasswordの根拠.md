# Task 1.8 問題文の 3 要件がどのコマンドで満たされるか（`maximum-prefix 100000 80 restart 5` の 1 行が 3 要件を全部満たす／`send-community extended` は解答 HTML に 0 件・ラボには 9 件＝IOS 自動付加／`neighbor password` の根拠は問題文 3 章で 6 セッション 12 行）

## 質問

```
q8について
- **80,000プレフィックスを超えた場合に警告メッセージを生成**すること。
- **100,000プレフィックスを超えた場合に、そのBGPセッションをシャットダウン**すること。
という問題の部分はどこで満たされている？

・vpnv4の設定をする時に
address-family vpnv4
  neighbor 100.255.254.6 activate
  neighbor 100.255.254.6 send-community extended

send-communityは必要ないの？R6の事前設定にはあるけど回答解説には含まれていない

・nei pass は問題文のどこで必要とわかる？
```

## 回答

---

## ① 80,000 警告 / 100,000 shutdown はどこで満たされているか

**`neighbor 100.3.21.2 maximum-prefix 100000 80 restart 5` の 1 行だけ。**
問題文の 3 つの箇条書きが、そのまま 3 つの引数に対応している。

```
neighbor 100.3.21.2 maximum-prefix 100000 80 restart 5
         ─────┬────             ──┬── ─┬─ ────┬───
              │                    │    │      │
              │                    │    │      └─ 「5分後に自動的に再確立」
              │                    │    └─ 「80,000 を超えたら警告」← 100000 の 80%
              │                    └─ 「100,000 を超えたらシャットダウン」
              └─ 「R3 が Data Center ルータから受信する」← R21 = DC
```

| 問題文の要件 | 対応する引数 |
|---|---|
| 80,000 を超えたら警告メッセージ | `80`（**パーセント指定**。100000 × 80% = 80,000） |
| 100,000 を超えたらセッションを shutdown | `100000` |
| 5 分後に自動再確立 | `restart 5` |

### 注意点 3 つ

**1. 第 2 引数はパーセントであって本数ではない**

`80000` と書きたくなるが % 指定。「上限 100,000 / 警告 80,000」= `100000 80`。
解答資料は 3 箇所とも `90` だが、**問題文の 80,000 から逆算すると `80`**（既出の矛盾）。

**2. なぜ R21（100.3.21.2）向けだけなのか**

問題文が「R3 が **Data Center ルータ**から受信するプレフィックス」と限定しているため。

| CE | IP | 拠点 | maximum-prefix |
|---|---|---|---|
| R11 | 100.3.11.2 | HQ | **不要** |
| **R21** | **100.3.21.2** | **Data Center** | **必要** |

HQ 側（R11）に付けると要件外の設定になる。

**3. `warning-only` を付けてはいけない**

`maximum-prefix` には `warning-only` キーワードがあり、付けると**警告だけ出してセッションを落とさない**。
問題文は「100,000 を超えたらシャットダウン」と明示しているので付けない。

また `restart 5` を省くと、落ちたセッションは**手動で `clear ip bgp` するまで復旧しない**。
「5 分後に自動的に再確立」の一文がこの引数を要求している。

---

## ② `send-community extended` は必要か

### 結論: 打たなくても動く。ただし打っておくのが安全（コストは 1 行）

リポジトリを数えた結果:

| ソース | `send-community` の出現数 |
|---|---|
| **解答 HTML 全体**（Task 1.2〜1.14 / Pattern 1・2・3 すべて） | **0 件** |
| `EI_v2.yaml`（ラボ初期コンフィグ） | **9 件** = R4・R5・R6 × 各 3 ピア |

そして 9 件**すべてが `activate` の直後、`address-family vpnv4` の中**にある。
`address-family ipv4 vrf fabd2`（CE 向け eBGP）には 1 件もない。

### この非対称が意味すること

解答の作者は**一度も `send-community extended` を打っていない**のに、事前設定済みの 3 台には全部入っている。
これは **IOS が VPNv4 アドレスファミリで neighbor を `activate` した時点で拡張コミュニティ送信を既定で有効化し、
running-config に自動で書き出す**動作と整合する。

VPNv4 では RT（= 拡張コミュニティ）が経路配布の根幹なので、送らない選択肢が実質存在しない。
だから IOS が面倒を見る。

### それでも打つべき理由

打ち忘れた場合の障害が**最も切り分けにくい形**で出る:

```
BGP セッションは全部 Established                   ← 正常に見える
show ip route vrf fabd2 に他拠点の経路が入らない   ← RT が付いていないので import できない
```

これは **RT 不一致（Task 1.8 の本題）とまったく同じ症状**で、原因の切り分けに時間を溶かす。
1 行足すコストはゼロなので、**R4/R5/R6 と同じ形にしておく**のが安全。

逆に「打ったら減点されるか」は心配不要。他の PE の running-config と同一の状態になるだけ。

## ③ `neighbor password` は問題文のどこで必要とわかるか

**問題文セクション 3 がそのまま根拠。ここだけ。**

```markdown
## 3. BGPセッションの認証

Global SP #1内のすべてのBGPセッションを、次のパスワードを使用して保護すること。

CCIE!nfr4
```

### 読み方の分解

| 問題文の語 | 読み替え |
|---|---|
| 「BGPセッションの**認証**」「**保護**すること」 | BGP における保護 = **TCP MD5 認証** = `neighbor <ip> password <pw>` |
| 「**Global SP #1 内の**」 | 範囲は R1〜R6。SP の外（CE）は対象外 |
| 「**すべての**BGPセッション」 | 該当する全セッションに漏れなく |
| パスワード `CCIE!nfr4` | 全台で 1 文字も違えてはいけない |

BGP で「パスワードを使って保護」と言われたら `neighbor password` 以外の選択肢は実質ない
（`ttl-security` は保護だがパスワードを使わない）。

### 範囲の確定 — 6 セッション / 設定は 12 行

| 機器 | BGP | 理由 |
|---|---|---|
| R1 / R2 | **なし** | 問題文 2 章「R1およびR2では、BGPを動作させてはならない」 |
| R3〜R6 | あり | PE 4 台 |

さらに「ルートリフレクタは使用しないこと」→ **4 台フルメッシュ** なのでセッションは 4C2 = **6 本**。

```
R3─R4   R3─R5   R3─R6   R4─R5   R4─R6   R5─R6
```

MD5 は両端に設定するので **各 PE に 3 行 × 4 台 = 12 行**。
「6 セッションだから 6 行」ではない。

### CE との eBGP が対象外である根拠

「Global SP #1 **内の**」という限定が根拠だが、実機側にも裏付けが 3 つある:

1. CE（R11 / R21 / R61 / R62 / R70）は AS 65001〜65007 で、**SP #1（AS 10000）の外**
2. CE 側の初期コンフィグに `password` が**1 行もない** — 付けたら即座にセッションが落ちる
3. 解答 config も PE 間 iBGP にしか `password` を付けていない

---

## 3 問の関係（同じ読み方の練習）

① と ③ は同じ構造。**問題文の 1 つの文が 1 つのコマンド（または 1 つの引数）に対応する。**

| 問題文 | コマンド |
|---|---|
| 80,000 で警告 / 100,000 で shutdown / 5 分で復旧 | `maximum-prefix 100000 80 restart 5`（1 行で 3 要件） |
| SP #1 内の全 BGP セッションを CCIE!nfr4 で保護 | `neighbor <PE> password CCIE!nfr4` × 12 行 |
| （記載なし） | `send-community extended` ← **問題文に対応する記述がない = 明示要件ではない** |

②が解答資料に無いのは **問題文が要求していないから**。
IOS が自動で入れる領域なので作問者も解答に書かなかった、という一貫した説明がつく。
