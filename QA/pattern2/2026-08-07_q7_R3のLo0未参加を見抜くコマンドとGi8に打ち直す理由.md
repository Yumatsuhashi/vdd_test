# Task 1.7 R3 の Lo0 が OSPF 未参加だと見抜く確認コマンド（RID に .3 が出るのは罠）と、設定済みの Gi8 に3行打つ理由

## 質問

```
interface Loopback0
ip ospf 1 area 0

これをR3で設定しているがこれはなんの確認コマンドからint lo0でospfが動いていないことがわかる？

加えて
interface GigabitEthernet8
ip ospf 1 area 0
ip ospf network point-to-point
mpls ip

int gi8は事前設定でospfが入っているはずなのになぜ設定している？
```

## 回答

### 前提：R3 の初期コンフィグ実測（EI_v2.yaml）

```
interface Loopback0
 ip address 100.255.254.3 255.255.255.255     ← ip ospf 無し
interface GigabitEthernet1     100.3.11.1/30  ← R11向け(CE)。ospf 無し
interface GigabitEthernet2     100.3.21.1/30  ← R21向け(CE)。ospf 無し
interface GigabitEthernet8
 ip address 100.0.13.2 255.255.255.252
 ip ospf 1 area 0                             ← ★これだけ入っている
router ospf 1
!                                             ← ★中身が空（network文なし・router-idなし）
```

**`router ospf 1` は器だけで中身が空**。在籍しているのは Gi8 一本のみ。
「プロセスが存在する＝設定済み」ではない。

## Q1. Lo0 で OSPF が動いていないと分かるコマンド

### 決め手：`show ip ospf interface brief`

**OSPF が有効な I/F しか行を出さない**コマンド。R3 では：

```
R3#show ip ospf interface brief
Interface    PID   Area    IP Address/Mask    Cost  State Nbrs F/C
Gi8          1     0       100.0.13.2/30      1     DR    1/1
```

**Lo0 の行が1行も無い＝ OSPF に入っていない。**
`show ip interface brief`（IP 視点の名簿）と違い、これは「OSPF 視点の在籍名簿」なので、
ここに無い＝在籍していない、と断定できる。

### 補強・別角度

| コマンド | 見るところ | R3 での結果 |
|---|---|---|
| `show ip protocols` | `Routing on Interfaces Configured Explicitly (Area 0):` のリスト | `GigabitEthernet8` **のみ**。Lo0 が無い |
| `show run interface Loopback0` | `ip ospf` 行の有無 | 無い（最も直接的） |
| `show ip ospf database router self-originate` | 自分の Type 1 LSA の stub link | `100.255.254.3/32` の stub link が**存在しない**（LSDB 側からの証明） |
| **`show ip route ospf \| i 100.255.254`（R1 で）** | 学習できている Lo0 の一覧 | **.3 と .5 が無い**（.2/.4/.6 のみ） |

### 本番で最速なのは最後の1つ

R1 で `show ip route ospf | i 100.255.254` を1回打つと、**6台分の Lo0 広告状況が一発で並ぶ**。
`.3` と `.5` が欠けている＝ R3 と R5 の Lo0 が未広告、と即断できる。
6台に個別ログインして `sh ip ospf int b` を打つより圧倒的に速い。

（.4 は Lo0 が /31 なので `100.255.254.4/31` として出る。Task 1.7 の既知の罠。）

### 最大の罠：RID に騙されない

R3 の OSPF ルータ ID は **`100.255.254.3` になる**。
`router ospf 1` に `router-id` が無いとき、IOS は
**「OSPF に参加しているか否かに関係なく」最も大きいループバックの IP を RID に採用する**から。

結果、R1 側の出力はこうなる：

```
R1#sh ip ospf nei
Neighbor ID     Pri   State      Dead Time   Address      Interface
100.255.254.3     1   FULL/DR    00:00:31    100.0.13.2   GigabitEthernet0/1
                  ↑ Lo0 の IP が堂々と出ている
```

**「RID に Lo0 の IP が出ている」≠「Lo0 が OSPF で広告されている」。**
RID は「名前」、広告は「経路」。別物。

ここを見間違えると波及する被害：

1. **LDP セッションが張れない** — LDP は相手の LDP-ID（＝ Lo0）宛 TCP 646 で張るため、Lo0 の IGP 到達性が必須
2. **Task 1.8 の VPNv4 iBGP が丸ごと落ちる** — `neighbor 100.255.254.x update-source Loopback0`
3. **prefix-suppression と併用で全滅** — コア間 /30 が LSA から消えるため、残る到達手段が Lo0 /32 だけになる

## Q2. 設定済みの Gi8 に3行打つ理由

**3行のうち「事前設定済み」なのは1行だけ。**

| 行 | R3 での状態 | 打つ理由 |
|---|---|---|
| `ip ospf 1 area 0` | ✅ **既に入っている（冪等・no-op）** | 6台共通テンプレとして残す。R3 では無害、**R5 では必須**（R5 は Gi8 に OSPF が無い） |
| `ip ospf network point-to-point` | ❌ **未設定。これが本命** | broadcast のままだと DR/BDR が選出され **Type 2 LSA が生成される**＝要件違反 |
| `mpls ip` | ❌ 未設定 | ラベルスイッチング有効化。`mpls ldp autoconfig area 0` があれば理論上不要だが打ち忘れ保険 |

### R3 は「Type 2 LSA を出している張本人」

`FULL/DR` が示す通り、R3（RID `100.255.254.3`）は R1（`100.255.254.1`）より RID が大きいので
**DR に選出されている**。DR ＝ Network LSA（Type 2）の生成担当。

問題文の要件:

> Global SP #1 内のどのルータの LSDB にも、Type 2 LSA が存在してはならない

に対し、**R3 が違反を作り出している側**。ここを P2P に変えないと
`show ip ospf database network` から `100.0.13.2` を Link State ID とする Type 2 LSA が消えない。

しかも **LSDB はエリア内全台で同一**なので、**R3 の 1 行の未設定が 6 台全部を要件違反にする**。

### 「R1 側だけ P2P にすればいい」は通用しない

ネットワークタイプは Hello パケットに含まれないため、片側だけ P2P にしても隣接自体は上がる。
しかし **broadcast 側（R3）は自分を DR に選出し続け、Network LSA を出し続ける**。
→ R1〜R6 の**全コア I/F に漏れなく**打つ必要がある。

### なぜ冪等な `ip ospf 1 area 0` を消さないのか

1行削るために機器ごとにブロックを作り分けると、本番でブロックの選択ミスが起きる。
6台共通テンプレとして貼り切るほうが速くて安全（打っても害はなく、「確認しなさい」要件の裏取りにもなる）。

## まとめ

| 質問 | 答え |
|---|---|
| Lo0 が OSPF 未参加と分かるコマンド | `show ip ospf interface brief`（Lo0 の行が無い）／最速は R1 で `show ip route ospf \| i 100.255.254` → .3 と .5 が欠落 |
| なぜ RID には .3 が出るのか | RID は「OSPF 参加の有無に関係なく」最大ループバック IP から自動選出。**RID ≠ 広告** |
| Gi8 の3行を打つ理由 | `ip ospf 1 area 0` のみ冪等。**`ip ospf network point-to-point` が本命**（R3 は DR ＝ Type 2 LSA の生成元）＋ `mpls ip` は保険 |
| `router ospf 1` があるのに未設定？ | R3 の `router ospf 1` は**中身が空**。プロセスの器だけで、在籍しているのは Gi8 一本 |
