# Task 1.11 「道①の入口は R5 だけ？R6 は？」と「道②のインターネット経路は SP_1 / SP_2 を通るのか」

## 質問

なぜR5だけが道1の入り口となっているの？R6もあるはずだよね
道2のインターネットをを使う場合はR61→R24の経路はどんな感じで移動する？SP_1,2というルーターがあるがこれを使うってこと？

## 回答

### Q1. なぜ R5 だけが「道①の入口」なのか

**R6 も PE。** 前回の図は **R61 から見た絵**だった。CE は 1 台につき PE 1 台にしか繋がっていない。

#### 配線の実物（EI_v2.yaml の links セクション）

| CE | 物理リンク | 対向 PE |
|---|---|---|
| R11（HQ） | Gi0/0 ↔ R3 Gi1 | **R3** |
| R21（DC） | Gi1 ↔ R3 Gi2 | **R3** |
| **R61（ブランチ3）** | **Gi0/0 ↔ R5 Gi1** | **R5** |
| R62（ブランチ3） | Gi0/0 ↔ R6 Gi1 | **R6** |
| R70（ブランチ4） | Gi0/0.100 ↔ R6 Gi2.100 | **R6** |

R61 が MPLS VPN に入る扉は **R5 しかない**。R6 は R62 と R70 の扉。

#### では「R6 の扉」から入ってくる分はどうするのか

| R6 の先 | 状況 | R6 にフィルタは？ |
|---|---|---|
| R70 | MPLS 経路は **VRF WAN の箱**、EIGRP 経路はグローバルの箱 → 比較すら起きない | 不要 |
| R62 | グローバル同士で衝突しうるが、**問題文が「スポークとしての R62 は無視」と明示** | 不要（対象外） |

→ **フィルタが必要なのは R5 の 1 台だけ**。
「R5 だけが入口」ではなく「**入口は複数あるが、塞ぐ必要があるのは R5 の扉だけ**」が正確な言い方。

#### 補足：R61 ↔ R62 の裏道は成立しない

R61 Gi0/1（10.6.99.1/30）と R62 Gi0/1（10.6.99.2/30）は直結していて、**R62 側は EIGRP を有効にしている**。

```ios
! R62 初期コンフィグ
router eigrp ccie
 af-interface GigabitEthernet0/1
  no passive-interface        ← R61 向けリンクで EIGRP 有効
 af-interface GigabitEthernet0/2
  no passive-interface
 af-interface GigabitEthernet0/3
  no passive-interface
 network 10.0.0.0
```

理屈上は「R6 → R62（BGP・グローバル）→ R61（EIGRP）」という裏道がありえるが、
**R62 に BGP → EIGRP の再配布がない**ので DC 経路は漏れない。
これも R6 にフィルタが不要な理由のひとつ。

### Q2. 道②（インターネット）の経路 — SP_1 を使う。SP_2 は使わない

#### まず重大な命名の罠

**CML のノード「SP_1」は、問題文の「Global SP #1」とは全くの別物。**

| 呼び名 | 実体 | AS | 役割 |
|---|---|---|---|
| **Global SP #1**（問題文の呼称） | R1・R2（P）＋ R3・R4・R5・R6（PE）の 6 台 | **10000** | MPLS L3VPN ＝ **道①** |
| **SP_1 ノード**（CML ラベル、hostname `SP1`） | ルータ **1 台** | **19999** | インターネット ISP ＝ **道②** |
| **SP_2 ノード**（hostname `SP2`） | ルータ 1 台。`Eth0/0 = 101.22.0.1/30` のみ | — | R22 の WAN 対向専用。**Pattern 2 では出番なし** |

Task 1.11 で使うのは **SP_1（AS 19999）だけ**。SP_2 は Q9 の `101.22.0.0/30` の対向で、
R22 が eBGP（AS 10001）を張るのは **Pattern 3 の Task 2.1 のみ**。

#### SP_1 の実体（EI_v2.yaml）

```ios
hostname SP1
interface Ethernet0/0   ip address 200.99.23.1 255.255.255.252   ! → R23 (DC)
interface Ethernet0/1   ip address 200.99.24.1 255.255.255.252   ! → R24（DMVPN ハブ）★
interface Ethernet0/2   ip address 200.99.12.1 255.255.255.252   ! → R12 (HQ)
interface Ethernet0/3   ip address 200.99.61.1 255.255.255.252   ! → R61（スポーク）★
interface Ethernet1/0   ip address 200.99.70.1 255.255.255.252   ! → R70（スポーク）★
interface Ethernet1/1   ip address 200.99.62.1 255.255.255.252   ! → R62
!
router bgp 19999
 redistribute static
 neighbor 200.99.24.2 remote-as 65002      ! R24
 neighbor 200.99.61.2 remote-as 65006      ! R61
 neighbor 200.99.62.2 remote-as 65006      ! R62
 neighbor 200.99.70.2 remote-as 65007      ! R70
 default-information originate
!
ip route 0.0.0.0 0.0.0.0 Null0             ! ★これを全員に配る
```

この `0.0.0.0/0` の配布が、問題文の
「**ブランチルータは、専用のVRFを使用してISPへ接続し、BGP経由でデフォルトルートを受信すること**」に対応する。

注: SP1 には R12（200.99.12.2）向けの BGP neighbor が**無い**。だから Task 1.9 で R12 は
`redistribute connected` するしかない（Q9 の説明と整合）。

#### R61 → R24 のパケットの旅（二重の袋）

```
① [R61 グローバル・テーブル]  10.2.114.0/30 宛のパケットが到着
      経路: D 10.2.114.0/30 via 10.200.0.1, Tunnel0   ← EIGRP で学んだ
      ↓
② [Tunnel0 でカプセル化]
      元のパケットを GRE で包み、さらに IPsec（3DES / MD5）で暗号化
      外側ヘッダ:  src 200.99.61.2  →  dst 200.99.24.2
      ↓  tunnel vrf WAN ＝「この外側ヘッダは VRF WAN のテーブルで引け」
③ [R61 VRF WAN テーブル]
      0.0.0.0/0 via 200.99.61.1   ← SP1(AS19999) から BGP で受信したデフォルト
      ↓  Gi0/4（vrf forwarding WAN, 200.99.61.2）から送出
④ [SP1 = インターネット]  Eth0/3 で受け → Eth0/1 へ転送
      ↓
⑤ [R24 Gi1 = 200.99.24.2]
      IPsec 復号 → GRE 解除 → 中身の元パケットが出てくる
      ↓
⑥ [R24 グローバル・テーブル]  10.2.114.0/30 は Gi2 の直結 → SW211 へ
```

**②③ が「外側の袋」＝ VRF WAN、①⑥ が「中身」＝ グローバル。**
`tunnel vrf WAN` と `vrf forwarding` の役割分担がそのままこの流れに対応する。

R70 も全く同じで、④ の SP1 の出入口が Eth1/0 ↔ Eth0/1 に変わるだけ。

#### 全体像

```
             ┌──── 道①: MPLS L3VPN (Global SP #1 / AS 10000) ────┐
             │                                                    │
   R24 ─ DC ─ R21 ── R3(PE) ══ R1/R2(P) ══ R5(PE) ── R61          │
   (ハブ)                                    ▲                     │
     │                                       └ ★ここに ACL 66      │
     │                                                             │
     └──── 道②: Internet (SP_1 ノード / hostname SP1 / AS 19999) ──┘
           R24 Gi1 ─ SP1 Eth0/1 … Eth0/3 ─ R61 Gi0/4
                        (この上に DMVPN/IPsec トンネル、中で EIGRP)

   SP_2 ノード ── R22 Gi1 (101.22.0.0/30)   ← このタスクとは無関係
```

### 調査中に見つかったラボの注意点：R61 の EIGRP に `network` 文がない

```ios
! R61（初期コンフィグ）              ! R70（初期コンフィグ）
router eigrp ccie                     router eigrp ccie
 address-family ipv4 unicast …         address-family ipv4 unicast …
  af-interface default                  af-interface default
   passive-interface                     passive-interface
  topology base                         topology base
  ← network 文なし ⚠️                   network 10.6.14.14 0.0.0.0
                                        network 10.200.0.0 0.0.0.255  ← Tunnel0 を含む
```

名前付き EIGRP でも `network` 文がないとインターフェースで EIGRP が有効にならない。
解答資料も R61 には `af-interface Tunnel0 / no passive-interface` しか追加しないため、
**このままだと R61 だけ EIGRP 隣接が上がらない可能性がある**。
実機で `show ip eigrp neighbors` が空なら `network 10.200.0.0 0.0.0.255` を追加する（R70 と同じ形）。
