# Task 1.12 `permit 10.0.0.0 0.255.255.255` はコマンドミスか（ワイルドカードマスクの話）

## 質問

permit 10.0.0.0 0.255.255.255 これはコマンドミス？

## 回答

### 結論：ミスではない。ワイルドカードマスクなのでこれで正しい

正本を確認済み。`original/RS コンフィグ パターン比較 (Task 1.2〜1.14).html` の
1826 行・3010 行・4026 行すべてに `permit 10.0.0.0 0.255.255.255` が同じ表記で入っている
（パターン1・2 共通。パターン3 はこの NAT 設定自体が無い）。転記ミスではない。

### サブネットマスクとワイルドカードマスクは別物

**ACL はサブネットマスクを使わない。**

| 記法 | 10.0.0.0/8 の場合 | 意味 |
|---|---|---|
| サブネットマスク | `255.0.0.0` | 1 = ネットワーク部 |
| **ワイルドカードマスク** | **`0.255.255.255`** | **0 = 一致必須 / 1 = 何でもいい** |

ビットが**反転**している。`0.255.255.255` は「第1オクテットだけ 10 と一致すればよく、
残り 3 オクテットは何でもいい」＝ `10.0.0.0/8`。

```
10.0.0.0        00001010 . 00000000 . 00000000 . 00000000
0.255.255.255   00000000 . 11111111 . 11111111 . 11111111
                └─一致必須─┘└──────── 何でもいい ────────┘
```

変換は `255.255.255.255 − サブネットマスク` で機械的に出せる。

| プレフィックス | サブネット | ワイルドカード |
|---|---|---|
| /8 | 255.0.0.0 | **0.255.255.255** |
| /16 | 255.255.0.0 | 0.0.255.255 |
| /24 | 255.255.255.0 | 0.0.0.255 |
| /30 | 255.255.255.252 | 0.0.0.3 |
| /32 | 255.255.255.255 | 0.0.0.0 |

### ⚠️ 逆に書くと「エラーは出ないのに動かない」

`permit 10.0.0.0 255.0.0.0` と書いても **IOS は何も文句を言わずに受け付ける**。しかし意味は:

```
permit 10.0.0.0 255.0.0.0
　→ 第1オクテットは何でもいい / 残り 3 オクテットは 0.0.0 と完全一致
　→ マッチするのは x.0.0.0 だけ（10.2.115.1 などは一致しない）
```

結果、NAT が 1 件も動かず「設定は入っているのに ping が通らない」という
一番デバッグしづらい状態になる。**ACL のマスクを間違えてもシンタックスエラーは出ない。**

### なぜ 10.0.0.0/8 という広い範囲なのか

R23 の inside 側とその先には DC の `10.2.x.x` が広がっている。

| I/F | IP | 接続先 | NAT 役割 |
|---|---|---|---|
| Gi2 | 10.2.115.1/30 | SW211 | `ip nat inside` |
| Gi3 | 10.2.215.1/30 | SW212 | `ip nat inside` |
| Gi1 | 200.99.23.2/30 | SP_1（ISP） | `ip nat outside` |
| Gi4 | no ip address | cEdge21 | — |

`10.2.0.0/16` や個別 /30 でも動くが、**プライベートアドレス全体を一括で拾う** `10.0.0.0/8` に
しておけば DC 内のどのセグメントから出ても漏れない。試験では広めに取る方が安全。

広くても危険がない理由が 2 つある:

1. **`ip nat inside` を付けた I/F から入った通信しか ACL を見ない** — Gi2/Gi3 以外から来たパケットは対象外
2. **inside → outside を跨ぐときだけ変換される** — Gi2 ↔ Gi3 のような内部同士の通信は NAT されない

つまり ACL の広さはインターフェース指定によって二重に絞り込まれている。

### 標準 ACL でよい理由

`ip nat inside source list` が見るのは**送信元アドレスだけ**なので標準 ACL で十分。
拡張 ACL にする必要はない。
（Telnet 側の `CCIETELNET` が拡張なのは、宛先ポート 23/3003 を見る必要があるため）

### 確認コマンド

```
R23# show access-lists CCIENAT
Standard IP access list CCIENAT
    10 permit 10.0.0.0, wildcard bits 0.255.255.255 (123 matches)   ← ヒットカウントを見る

R23# show ip nat statistics        ! inside/outside I/F と参照 ACL の対応
R23# show ip nat translations
```

`show access-lists` で **`wildcard bits`** と明記されるので、迷ったらこれで意図と合っているか確認できる。
