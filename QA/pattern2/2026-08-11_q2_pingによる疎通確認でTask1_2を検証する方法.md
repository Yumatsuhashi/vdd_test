# Task 1.2 を ping（疎通確認）で検証する方法

## 質問

なんか、ping を打つとか　通信疎通確認する系でないの？

## 回答

### 結論

- **Branch #3 は ping だけでトランク要件を完全に証明できる**（config 変更不要）
- **HQ はそのままでは ping できない**。SW110 に検証用 SVI を一時作成するか、STP の Root ID 一致で見る
- **アクセスポート4本（SW110 Gi0/0-0/1・SW610 Gi0/0-0/1）は物理的に未接続なので ping 不可能**。設定を読むしかない

---

### ① Branch #3 — ping で完全検証（config 変更なし）

#### なぜ ping が有効なのか

```
SW601 Gi0/0 ── SW602 Gi0/0    ← no switchport / 10.6.109.1 255.255.255.252（L3 ルーテッド）
SW601 Gi2/0 ── SW610 Gi2/0    ← trunk
SW602 Gi2/0 ── SW610 Gi2/1    ← trunk
```

**SW601 と SW602 の直結リンクは L3 ルーテッドポートなので VLAN 2000/2001 のフレームは通れない。**
よって両者間の L2 経路は **SW610 経由の一本道**に強制される。
これが「ping が落ちた ＝ トランク設定が悪い」と断定できる根拠。

#### ping セット

| 打つ場所 | コマンド | 通る経路 | 証明できる要件 |
|---|---|---|---|
| SW601 | `ping 10.6.100.3` | SW601 Gi2/0 → SW610 Gi2/0 → SW610 Gi2/1 → SW602 Gi2/0 | **トランク4本 × VLAN2000** |
| SW601 | `ping 10.6.101.3` | 同上 | **トランク4本 × VLAN2001** ★最重要 |
| SW601 | `ping 10.6.100.10` | SW601 Gi2/0 → SW610 Gi2/0 のみ | SW601–SW610 間だけを切り分け |
| SW602 | `ping 10.6.100.10` | SW602 Gi2/0 → SW610 Gi2/1 のみ | SW602–SW610 間だけを切り分け |
| SW610 | `ping 10.6.100.2` / `ping 10.6.100.3` | Gi2/0 / Gi2/1 を個別に | SW610 の左右トランクを分離判定 |

同一サブネット宛なので L3 ルーティングは介在せず、SVI から必ず L2 で出ていく。

**`ping 10.6.101.3` が落ちたら SW610 の `switchport trunk allowed vlan` に 2001 が無いと断定できる**
（初期値が `1,2000` で 2001 欠落。Task 1.2 最大の罠）。

#### おまけ: `224.0.0.1` で1発点呼

```
SW601# ping 224.0.0.1 source Vlan2000 repeat 2

Reply to request 0 from 10.6.100.3, 4 ms      ← SW602 が VLAN2000 に居る
Reply to request 0 from 10.6.100.10, 4 ms     ← SW610 も居る
```

`224.0.0.1` は全ホストマルチキャストで、同一セグメントの IOS 機器が全員返事をする。
**「VLAN 2000 のブロードキャストドメインに誰がいるか」の点呼が1コマンドで取れる。**
`ip multicast-routing` は不要（リンクローカルなのでルーティングを介さない）。

VLAN2001 は `ping 224.0.0.1 source Vlan2001` — SW610 は Vlan2001 SVI を持たないので **SW602 だけ返答するのが正解**。

（`source` 付きインライン形式が通らない IOS なら、引数なしの `ping` で拡張 ping プロンプトに入り、
Target = 224.0.0.1、Extended commands = yes、Source = Vlan2000 と答える）

#### 参考: Branch #3 の SVI 一覧

| 機器 | Vlan2000 | Vlan2001 |
|---|---|---|
| SW601 | 10.6.100.2 | 10.6.101.2 |
| SW602 | 10.6.100.3 | 10.6.101.3 |
| SW610 | 10.6.100.10 | **SVI なし**（L2 スイッチングだけなので不要） |

**⚠️ HSRP は判定に使わない**: Vlan2000 は SW601 だけ `standby version 2`（バージョン不一致）、
Vlan2001 は SW601 が `standby 101` / SW602 が `standby 0`（グループ不一致）で初期状態から壊れている。
`show standby brief` は L2 が正常でも Active/Active に見える。実IP同士の ping には一切影響しない。

### ② HQ — そのままでは ping で検証できない

```
SW110 Gi1/0-1 ── SW101 Gi1/2-3   (SW110 Po1 ⇔ SW101 Po1)
SW110 Gi1/2-3 ── SW102 Gi1/2-3   (SW110 Po2 ⇔ SW102 Po2)
SW101 Gi2/0-1 ── SW102 Gi2/0-1   (Po3・直結！)
```

- SW101 Vlan2000 = 10.1.100.2 / Vlan2001 = 10.1.101.2
- SW102 Vlan2000 = 10.1.100.3 / Vlan2001 = 10.1.101.3
- **SW110 は SVI を持たない純 L2**

`ping 10.1.100.3`（SW101→SW102）は **Po3 の直結を通ってしまい、Po1/Po2/SW110 を1ミリも検証しない**。
SW110 は ping の宛先にもなれない。よって手を1つ加える必要がある。

#### 手A（推奨・確実）: SW110 に検証用 SVI を一時作成

```
! SW110
interface Vlan2000
 ip address 10.1.100.10 255.255.255.0
 no shutdown
!
interface Vlan2001
 ip address 10.1.101.10 255.255.255.0
 no shutdown
```

```
SW110# ping 224.0.0.1 source Vlan2000 repeat 2
Reply to request 0 from 10.1.100.2, 4 ms     ← Po1 が VLAN2000 を通している
Reply to request 0 from 10.1.100.3, 4 ms     ← Po2 が VLAN2000 を通している

SW110# ping 224.0.0.1 source Vlan2001 repeat 2
Reply to request 0 from 10.1.101.2, 4 ms
Reply to request 0 from 10.1.101.3, 4 ms
```

**SW101 と SW102 の両方から返れば、Po1・Po2 の両方がその VLAN を通していることが一撃で証明される。**
片方しか返らなければ、返ってこない側の Po が犯人。

個別にやるなら `ping 10.1.100.2`（Po1 経由）/ `ping 10.1.100.3`（Po2 経由）。

> ⚠️ **確認後は `no interface Vlan2000` / `no interface Vlan2001` で必ず削除する。**
> Task 1.2 の SW110 は純 L2 が題意であり、余計な SVI は減点対象になり得る。
> なお SVI を作っても L2 VLAN データベースには影響しない（q13 の「SVI ≠ L2 VLAN」と同じ話）。

#### 手B（無変更）: STP の Root Bridge 一致で見る

```
show spanning-tree vlan 2000 | include Root ID|Address
show spanning-tree vlan 2001 | include Root ID|Address
```

SW101 / SW102 / SW110 の3台で **Root ID（Priority + MAC Address）が一致していれば、
その VLAN の L2 ドメインが3台に跨って繋がっている**。
トランクが VLAN を通していなければ SW110 は孤立して自分をルートに選び、値がズレる。
BPDU が実際に流れていることの確認なので、これも実質的な疎通確認。

#### 手C（無変更・補助）: MAC アドレステーブル

```
SW110# show mac address-table vlan 2000
SW110# show mac address-table vlan 2001
```

SW101/SW102 の SVI の MAC が Po1 / Po2 に載っていれば、そのポートでその VLAN のフレームが流れた証拠。
ARP はブロードキャストなので、SW101 で `clear arp` → `ping 10.1.100.3` を打てば SW110 の Po1 に学習が入る。
（ただし ARP 応答はユニキャストで Po3 を直行するため、Po2 側は SW102 から同じことをやる必要がある）

### ③ アクセスポート4本は ping 不可能（これは仕様）

`EI_v2.yaml` の links セクションに **`SW110-GigabitEthernet0/*` と `SW610-GigabitEthernet0/*` の定義が存在しない**。
つまり要件表の「タグなし」4行のポートには物理的に何も繋がっていない。

- `show interfaces status` で `notconnect` と出るが**これは異常ではない**
- STP にも載らない（STP は up ポートのみ）
- ping の相手もいない

→ **この4行だけは `show vlan brief` か `show interfaces switchport` で設定を読むしかない。**

---

### 実行順（疎通確認ベース）

```
1. SW601:  ping 10.6.100.3            → OK なら VLAN2000 のトランク4本クリア
2. SW601:  ping 10.6.101.3            → OK なら VLAN2001 もクリア（本命）
   落ちたら → SW610: show interfaces trunk で 2001 の有無を確認
              → interface range Gi2/0-1 / switchport trunk allowed vlan add 2001
3. SW110:  検証用 SVI 2本を作成
           → ping 224.0.0.1 source Vlan2000 / Vlan2001
           → SW101(.2) と SW102(.3) の両方から返るか確認
           → no interface Vlan2000 / no interface Vlan2001 で削除
4. show vlan brief で SW110 Gi0/0=2000・Gi0/1=2001、SW610 Gi0/0=2000・Gi0/1=2001
```

現時点の SW110 は手順3・4とも落ちるはず（Gi0/0-0/1 が VLAN 1 のまま、Gi1/0-1/3 のトランク／channel-group が消失）。
