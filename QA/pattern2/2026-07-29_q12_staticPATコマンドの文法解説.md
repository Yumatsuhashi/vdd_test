# static PAT コマンドの文法解説（ip nat inside source static tcp ...）

## 質問

ip nat inside source static tcp 10.2.255.23 80 200.99.23.2 2002 extendable
これはポート80のlo0をポート2002のgi1に変換している？問題文のどの部分を満たすためにやっているのか文法から解説して

## 回答

### コマンドの文法分解

構文: `ip nat inside source static tcp <local-ip> <local-port> <global-ip> <global-port> [extendable]`

| トークン | 値 | 意味 |
|---|---|---|
| `ip nat inside source static` | — | 固定（1対1）の変換エントリを作る（`list ... overload` の動的PATではない） |
| `tcp` | — | IPアドレスだけでなくポート番号も含めて変換する＝PAT（Port Address Translation） |
| `10.2.255.23 80` | local-ip / local-port | inside local＝R23内部の実体（Loopback0の実IP・TCP80、`ip http server` の待ち受けポート） |
| `200.99.23.2 2002` | global-ip / global-port | inside global＝外側から見えるアドレス・ポート。`200.99.23.2` はR23のGigabitEthernet1（outside）自身のIP（`EI_v2.yaml` で確認済み） |
| `extendable` | — | 同じglobal-IP（`200.99.23.2`）を使う他のNATエントリ（`ip nat inside source list CCIENAT interface GigabitEthernet1 overload`）と衝突・曖昧にならないよう明示的に区別する |

### 変換の向き（ユーザーの理解の訂正）

「Lo0のポート80をGi1のポート2002に変換している」は向きが逆。正しくは：

- **outside → inside 方向（主目的）**: 外部から `200.99.23.2:2002` 宛てに来た通信の**宛先を** `10.2.255.23:80`（Loopback0）**に書き換えて**内部へ転送する
- inside → outside 方向（戻りパケット）: Loopback0:80 発の応答は送信元が `200.99.23.2:2002` に書き換えられて外部へ出る

「Gi1のポート2002」はLo0のポート80への入口（グローバル側の窓口）であり、Gi1自体が宛先ではない。Gi1は外側から見えるIPアドレスの提供元（outsideインターフェース）として使われているだけ。

### 問題文との対応

問題文（`Questions/pattern2/pattern2_q12.md`）: 「R23では、ポート2002宛ての通信をTCPポート80へ変換し、宛先アドレスをR23のLoopback0インターフェイスへ変換すること。この変換にはスタティックPATを使用すること。」

| 問題文の要素 | 対応するコマンド部分 |
|---|---|
| 「ポート2002宛ての通信」 | `200.99.23.2 2002`（global-port） |
| 「TCPポート80へ変換」 | `10.2.255.23 80`（local-port） |
| 「宛先アドレスをLoopback0へ変換」 | `10.2.255.23`（local-ip = R23 Lo0） |
| 「スタティックPATを使用」 | `ip nat inside source static tcp` 構文自体 |

`extendable` は問題文に明記はないが、同じ `200.99.23.2` を動的overload PATでも使っているため、static PATエントリと動的overloadエントリが同じグローバルIPを共有しても矛盾なく共存できるようにする技術的な理由。
