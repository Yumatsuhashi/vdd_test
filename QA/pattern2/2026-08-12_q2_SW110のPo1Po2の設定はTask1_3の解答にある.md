# Task 1.2 SW110 の Po1/Po2 の設定が解答に無いのでは？（→ Task 1.3 の解答に入っている）

## 質問

task2について
SW110    Po1、Po2 にも設定しないといけないけど回答になくない？

```
interface GigabitEthernet0/0
switchport
switchport mode access
switchport access vlan 2000

interface GigabitEthernet0/1
switchport
switchport mode access
switchport access vlan 2001
```

## 回答

指摘は正しい。ただし**「解答に無い」のではなく、SW110 の Po1/Po2 は Task 1.3 の解答に入っている**。

### Task 1.3 の SW110 解答（`Answers/pattern2/pattern2_q3.md`）

```
no interface port-channel 1
no interface port-channel 2

interface range GigabitEthernet1/0-1          ← Po1
switchport
switchport trunk encapsulation dot1q
switchport mode trunk
switchport trunk allowed vlan 1,2000,2001     ← ★ Task 1.2 の「Po1 タグあり」要件はここ
channel-group 1 mode active
no shutdown

interface range GigabitEthernet1/2-3          ← Po2
switchport
switchport trunk encapsulation dot1q
switchport mode trunk
switchport trunk allowed vlan 1,2000,2001     ← ★ Task 1.2 の「Po2 タグあり」要件はここ
channel-group 2 mode active
no shutdown
```

SW101（Po1/Po3）・SW102（Po2/Po3）もまったく同じ構造で、
**HQ 3台とも Po のタグ付け設定は Task 1.3 側にまとめて書かれている。**

### なぜ Task 1.2 側に書かれないのか

**① 初期コンフィグで Po1/Po2 が既にトランクになっている**

```
interface Port-channel1
 switchport trunk encapsulation dot1q
 switchport mode trunk          ← 許可VLAN制限なし＝デフォルトで全VLAN(1-4094)をタグ付き許可
```

Cisco のトランクは `switchport trunk allowed vlan` を書かない限り全 VLAN 許可なので、
**「VLAN 2000/2001 をタグ付きで転送する」という Task 1.2 の要件だけを見れば初期状態で既に成立**している。

**② Po を作り直すのは Task 1.3 の仕事だから**

Task 1.3 は EtherChannel（802.3ad/LACP）と STP の課題で、`no interface port-channel 1` から始めて
物理ポート側で作り直す。そのタイミングで allowed vlan も一緒に明示的に絞る構成。
Task 1.2 で先に書いてしまうと Task 1.3 の `no interface port-channel` で消える。

### 責任分界

| 観点 | 担当タスク | SW110 の初期状態 |
|---|---|---|
| Po1/Po2 が VLAN2000/2001 を**タグ付き転送**する | **Task 1.2** | トランク＋全VLAN許可で成立済み → 追加不要 |
| Po1/Po2 が **LACP で正しくバンドル**する | **Task 1.3** | Po1 は `mode on`（LACPでない）、Po2 は passive↔passive で不成立 → 要修正 |

過去の QA（`2026-07-30_q2_PoとGiは別要件でありPoは初期設定済み.md`）は前者しか書いていなかった。
「Po にも設定が要るはず」という感覚は正しく、**最終的な config としては Po1/Po2 にも
`switchport trunk allowed vlan 1,2000,2001` が入る**（Task 1.3 の解答として）。

### ⚠️ ただし今の実機ラボでは前提が崩れている

`show vlan brief`（2026-08-11 実行）で **SW110 の Gi1/0・Gi1/1・Gi1/2・Gi1/3 が全部 `1 default` に出ていた**。
初期コンフィグのトランク＋`channel-group` が消えている状態。

判定根拠: 同じラボの SW101 では、同じ立場の Gi1/2-3・Gi2/0-1 が VLAN 1 の行から消えている
（＝トランクとして認識されているので `show vlan brief` に載らない）。この対照が証拠になる。

**この状態では「初期状態で成立済み」という前提が崩れるので、Task 1.3 の SW110 config をそのまま打つ必要がある。**
Task 1.2 の時点で打っても Task 1.3 と矛盾しない（Task 1.3 は rapid-pvst と portfast を足すだけ）。

確認コマンド:

```
show run | section ^interface Port-channel
show run | section ^interface GigabitEthernet1/
show etherchannel summary
```
