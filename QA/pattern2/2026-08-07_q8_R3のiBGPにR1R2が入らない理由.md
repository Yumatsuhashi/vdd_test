# Task 1.8 R3 の iBGP neighbor に R1/R2（100.255.254.1/.2）が入らない理由（P ルータは BGP 禁止＝BGP-free core／転送は外側ラベル1枚で完結／「経路上にいる」≠「ピアである」／RR 禁止でフルメッシュ3台／ピア5本の検算）

## 質問

```
q8について
router bgp 10000
 bgp router-id 100.255.254.3
 no bgp default ipv4-unicast
 neighbor 100.255.254.4 remote-as 10000
 neighbor 100.255.254.4 update-source Loopback0
 neighbor 100.255.254.4 password CC!E!nfr4
 neighbor 100.255.254.5 remote-as 10000
 neighbor 100.255.254.5 update-source Loopback0
 neighbor 100.255.254.5 password CC!E!nfr4
 neighbor 100.255.254.6 remote-as 10000
 neighbor 100.255.254.6 update-source Loopback0
 neighbor 100.255.254.6 password CC!E!nfr4

の部分でR1,2以外を指定しているけどこれはなぜ？解説して欲しい
```

## 回答

---

## ① 直接の根拠: 問題文が明示的に禁止している

```markdown
## 2. Pルータの構成

ルータ **R1およびR2** を、P（Provider）ルータとして構成すること。

- R1およびR2では、BGPを動作させてはならない。   ← ここ
- R1およびR2は、ラベルに基づいてパケットを転送すること。
```

「BGP を動作させてはならない」= **R1/R2 は BGP ピアになり得ない**。
だから R3 の neighbor から `.1` と `.2` が抜けている。

### アドレスの対応

`100.255.254.x` は全機の Loopback0 で、末尾が機器番号。

| IP | 機器 | 役割 | R3 の neighbor に入るか |
|---|---|---|---|
| 100.255.254.**1** | R1 | **P** | ❌ BGP 禁止 |
| 100.255.254.**2** | R2 | **P** | ❌ BGP 禁止 |
| 100.255.254.**3** | R3 | PE | —（自分） |
| 100.255.254.**4** | R4 | PE | ✅ |
| 100.255.254.**5** | R5 | PE | ✅ |
| 100.255.254.**6** | R6 | PE | ✅ |

連番の中で `.1` と `.2` だけ飛んでいるので不自然に見えるが、**PE か P かで綺麗に切れている**。

---

## ② なぜ P ルータに BGP が要らないのか（BGP-free core）

MPLS L3VPN の最大の設計上の利点。
**P ルータは顧客の VPN 経路を 1 本も知らない。ラベルを貼り替えるだけ。**

```
   R11(CE)      R3(PE)         R1(P)      R2(P)        R6(PE)      R62(CE)
  ┌──────┐    ┌────────┐    ┌───────┐  ┌───────┐   ┌────────┐   ┌──────┐
  │ AS   │────│ VRF    │────│ ラベル │──│ ラベル │───│ VRF    │───│ AS   │
  │65001 │eBGP│ fabd2  │    │ 交換のみ│  │交換のみ│   │ fabd2  │eBGP│65006 │
  └──────┘    └────────┘    └───────┘  └───────┘   └────────┘   └──────┘
                    ╚══════════ iBGP VPNv4 ══════════╝
                        R1/R2 を「通過」するが「参加」しない
```

### 転送時に何が起きているか（2 段ラベル）

R11 → R62 宛のパケットが R3 に来たときの動き:

| ホップ | 見ているもの | 動作 |
|---|---|---|
| R3（PE） | IP + VRF | **VPN ラベル**（R6 が配布）と**トランスポートラベル**（LDP）を 2 枚 push |
| R1（P） | **外側ラベルのみ** | swap して R2 へ。内側ラベルも IP ヘッダも**見ない** |
| R2（P） | **外側ラベルのみ** | R6 の Lo0 への最終手前なので pop（PHP） |
| R6（PE） | VPN ラベル | pop して VRF fabd2 の RIB で転送 |

R1/R2 が見るのは**外側のラベル 1 枚だけ**。中身が誰の VPN の何の宛先かを知る必要が一切ない。だから:

- **VRF 不要**（Task 1.8 の解答に R1/R2 が出てこない理由）
- **BGP 不要**（今回の質問の答え）
- **必要なのは OSPF + LDP だけ**（それが Task 1.7）

### 「打つと何を失うか」

R1/R2 に iBGP を張ると、要件違反であることに加えて
**コアルータが全顧客の全 VPN 経路を保持する**ことになる。
顧客が増えるほどコアのメモリと収束時間が悪化し、MPLS L3VPN を採用する意味そのものが消える。

---

## ③ 重要な区別: 「経路上にいる」≠「ピアである」

**R3↔R6 の iBGP セッションは物理的に R1 と R2 を通過する。**

実際の配線（EI_v2.yaml links）:

```
R3 ── R1 ── R2 ── R6
     (P)   (P)
```

- R1 に繋がる PE: R3（Gi0/1）, R5（Gi0/2）
- R2 に繋がる PE: R4（Gi0/1）, R6（Gi0/2）
- R1 Gi0/0 ↔ R2 Gi0/0

| レイヤ | R1/R2 の関与 |
|---|---|
| **物理・IP 転送** | ✅ 通す（TCP 179 のパケットを中継） |
| **OSPF** | ✅ 参加（Lo0 の到達性を提供 = Task 1.7） |
| **LDP** | ✅ 参加（ラベル配布） |
| **BGP** | ❌ **参加しない**（通すだけ） |

iBGP は `update-source Loopback0` によるマルチホップセッションなので、
**間に何台ルータがあっても直接ピアになれる**。R1/R2 にとってはただの TCP パケットが素通りしているだけ。

> 逆に言えば、**R1/R2 が OSPF で Lo0 を配っていなければ R3↔R6 の iBGP は張れない**。
> Task 1.7 が Task 1.8 の前提である理由がこれ。
> **P ルータは BGP に「参加しない」が「不可欠」**という関係。

---

## ④ なぜ「3 台」なのか

問題文にもう 1 つ根拠がある。

```markdown
### VPNv4ルートの交換
- PEルータ同士でVPNv4ルートを交換できるようにすること。
- ルートリフレクタは使用しないこと。      ← ここ
```

RR 禁止 = **フルメッシュ**。PE は R3/R4/R5/R6 の 4 台なので、各 PE は**自分以外の 3 台**と張る。

```
      R3 ───── R4
      │ ╲     ╱ │
      │   ╲ ╱   │        4C2 = 6 セッション
      │   ╱ ╲   │        各 PE から見ると 3 本
      R5 ───── R6
```

iBGP は学習した経路を他の iBGP ピアに再広告しない（split horizon）ため、
RR を使わないならフルメッシュが必須。

---

## ⑤ クロスチェック: ピア数の要件と一致する

問題文は「R3 には、アクティブな BGP ピアが **5 つ**存在すること」と要求している。

| # | ピア | 種別 | AF |
|---|---|---|---|
| 1〜3 | R4 / R5 / R6（Lo0） | iBGP | vpnv4 |
| 4 | R11（100.3.11.2） | eBGP | ipv4 vrf fabd2 |
| 5 | R21（100.3.21.2） | eBGP | ipv4 vrf fabd2 |

**ちょうど 5 本**。もし R1/R2 を入れたら 7 本になり要件そのものに違反する。
**「5 つ」という数字が、R1/R2 を除外することの検算になっている。**

---

## ⑥ 実機での裏付け

`EI_v2.yaml` の R1/R2 の初期コンフィグには **`router bgp` も `vrf` も 1 行も存在しない**。
あるのは `router ospf 1` だけ。

```
# R1 初期コンフィグ（抜粋）
interface Loopback0
 ip address 100.255.254.1 255.255.255.255
 ip ospf 1 area 0
...
router ospf 1
!                    ← ここで終わり。BGP も VRF も無い
```

→ **R1/R2 は Task 1.8 で作業ゼロ**。「BGP を動作させてはならない」は、何もしないことで既に満たされている。

## まとめ

| 問い | 答え |
|---|---|
| なぜ `.1` `.2` が無いのか | R1/R2 は **P ルータ**で、問題文が BGP を明示的に禁止しているから |
| P に BGP が要らない理由 | 転送は**外側ラベル 1 枚**だけで完結する（BGP-free core） |
| R1/R2 は無関係なのか | いいえ。**OSPF/LDP では不可欠**。BGP に「参加しない」だけで、セッションは通過する |
| なぜ 3 台なのか | RR 禁止 → PE 4 台フルメッシュ → 自分以外の 3 台 |
| 検算 | 3(iBGP) + 2(eBGP) = **5** = 問題文の「ピア 5 つ」と一致 |
