# Task 1.3 「この設定が必要だ」と判断するための確認コマンド（EtherChannel の事前チェック）

## 質問

```
interface range GigabitEthernet1/2-3
switchport
switchport trunk encapsulation dot1q
switchport mode trunk
switchport trunk allowed vlan 1,2000,2001
channel-group 1 mode active
no shutdown

interface range GigabitEthernet2/0-1
switchport
switchport trunk encapsulation dot1q
switchport mode trunk
switchport trunk allowed vlan 1,2000,2001
channel-group 3 mode active
no shutdown
```

CCIE_train_hub/Questions/pattern2/pattern2_q3.md において「この設定が必要だ」と思う必要がある　その確認をするとしたらどんなコマンドが必要？

## 回答

### 結論 — この2ブロックは「必要度」が違う

貼られた config は SW101 のもの。`EI_v2.yaml` の初期コンフィグと突き合わせると、Gi1/2-3 と Gi2/0-1 で状況が正反対になっている。ここを見抜くのが確認作業の目的。

| 対象 | 初期コンフィグの状態 | 本当に必要な差分 |
|---|---|---|
| **Gi1/2-3**（→SW110, Po1） | trunk/dot1q は入っているが **`channel-group` が無い** | `channel-group 1 mode active` ＋ `allowed vlan` |
| **Gi2/0-1**（→SW102, Po3） | **`channel-group 3 mode active` が既に入っている** | `allowed vlan 1,2000,2001` **だけ** |

つまり Gi2/0-1 のブロックは大半が再投入（冪等）で、EtherChannel 3 は初期状態で既に成立している。

### 確認コマンド（実行順）

#### 1. `show etherchannel summary` ← 主役

これ一発で「どの Po にメンバーが居ないか」「LACP かどうか」が両方見える。SW101 の期待出力:

```
Group  Port-channel  Protocol    Ports
------+-------------+-----------+---------------------
1      Po1(SD)          -                              ← メンバー0・ダウン＝設定必要
3      Po3(SU)         LACP        Gi2/0(P) Gi2/1(P)   ← 既に成立済み
```

判定基準:

- **Ports 欄が空 / `(SD)`** → その Po はメンバー未割当 ＝ `channel-group` が必要
- **Protocol 欄が `-`** → `mode on`（静的）で動作 ＝ 802.3ad（LACP）要件を満たさない → `mode active` へ要修正
- **`(I)` / `(s)`** → メンバーはいるがバンドル不成立（LACP ネゴ失敗）

#### 2. 対向側でも同じコマンドを打つ（必須）

自分側だけ見ても判断が完結しない。実際、対向側に2つ罠がある:

```
SW110:  1  Po1(SU)   -      Gi1/0(P) Gi1/1(P)   ← mode on ＝ LACPでない → 802.3ad要件違反
SW110:  2  Po2(SD)  LACP    Gi1/2(I) Gi1/3(I)   ← SW102側もpassive
SW102:  2  Po2(SD)  LACP    Gi1/2(I) Gi1/3(I)   ← passive同士でLACP開始せず不成立
```

`show lacp neighbor` を Gi1/2 で打って**ネイバーが空**なら、対向が `mode on` か passive-passive で LACPDU が来ていない証拠。`show lacp counters`（LACPDU sent/recv が 0）でも同じことが確認できる。

LACP モードの組み合わせ表:

| 自分 \ 対向 | active | passive | on |
|---|---|---|---|
| active | ○成立 | ○成立 | ×不成立 |
| passive | ○成立 | **×不成立** | ×不成立 |
| on | ×不成立 | ×不成立 | △成立（LACPでない＝802.3ad要件違反） |

#### 3. `show run interface GigabitEthernet1/2` / `show run | section GigabitEthernet`

summary で当たりを付けたら実際の投入内容を直接見る。`channel-group` 行の有無と mode（active / passive / on）がここで確定する。

#### 4. `show interfaces trunk` ← allowed vlan が必要かの判定

```
Port      Vlans allowed on trunk
Po3       1-4094        ← 未制限。allowed vlan コマンドが必要
Po3       1,2000-2001   ← 既に絞り込み済み。投入不要
```

「Vlans allowed on trunk」セクションが `1-4094` なら制限コマンドは未投入。下の「allowed and active in management domain」セクションは実在 VLAN しか出ないので混同注意（`2026-07-31_q2_SW602で既に絞られたトランクは適用済みの証拠.md` と同じ読み方）。

#### 5. `show cdp neighbors` ← 問題文の表とトポロジの一致確認

問題文の表（SW101 GE1/2-3 ↔ SW110 GE1/0-1）が実機と合っているかの裏取り。ラボ実配線は以下で一致している:

```
SW110-GigabitEthernet1/0 <-> SW101-GigabitEthernet1/2
SW110-GigabitEthernet1/1 <-> SW101-GigabitEthernet1/3
SW101-GigabitEthernet2/0 <-> SW102-GigabitEthernet2/0
SW101-GigabitEthernet2/1 <-> SW102-GigabitEthernet2/1
```

#### 6. 個々の行が必要かの確認（補助）

| config 行 | 確認コマンド | 「必要」の判定 |
|---|---|---|
| `switchport` | `show interfaces Gi1/2 switchport`（Switchport: Enabled/Disabled） | Disabled ＝ ルーテッドポート → 必要。SW101 の Gi1/2-3・Gi2/0-1 は既に L2（`no switchport` は Gi0/0-0/2 のみ） |
| `switchport trunk encapsulation dot1q` | `show interfaces Gi1/2 switchport`（Administrative Trunking Encapsulation） | 初期コンフィグで投入済み。ISL 対応機では省略不可なので入れておく分には無害 |
| `switchport mode trunk` | 同上（Administrative Mode: trunk か dynamic auto か） | 投入済み |
| `no shutdown` | `show interfaces status` / `show ip interface brief` | `disabled` / `administratively down` なら必要。初期状態は up |
| （参考）STP 側 | `show spanning-tree summary` | `pvst` と出る → `rapid-pvst` への変更が必要 |

### 最小手順でまとめると

```
show etherchannel summary          ← SW101 / SW102 / SW110 の3台すべてで
show interfaces trunk              ← 許可VLANの現状
show run | section GigabitEthernet ← channel-group の有無と mode
show cdp neighbors                 ← 表と実配線の一致
```

この4つで「Po1 はメンバー0 だから作る必要がある」「Po3 は既にあるので allowed vlan だけ」「SW110 の Po1 は `mode on` なので 802.3ad 要件を満たさず要修正」「Po2 は passive 同士で組めていない」という判断が全部つく。

### なぜ解答が `no interface port-channel 1/3` から始まるのか

初期コンフィグの Po1/Po3 には trunk 設定が入っているが許可 VLAN が未制限。Po を一度削除して物理ポート側の設定から再生成することで、Po に残った古い設定を確実に消して整合を取っている。
