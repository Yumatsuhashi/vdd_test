# Task 1.6 — `key chain CCIE_MD5` のお手本は実機のどこかにあるか（R62 コピペ戦略の射程）

## 質問

q6について
R62においてsh run | sec eigrpするとeigrpの設定コンフィグを覚えなくてもそれをコピペできるよね
それと同じ要領で

```
key chain CCIE_MD5
 key 1
  key-string CC!E!nfr4
```

これもどこかに設定されていてお手本を観れるのかなと思ったけどそれは違う？

## 回答

**違う。key chain の実体はラボ内のどこにも存在しない。** ここだけは暗記が必要。

### 根拠（EI_v2.yaml 全文 grep）

| 検索文字列 | ヒット数 | 場所 |
|---|---|---|
| `key chain` | **0 件** | — |
| `key-string` | **0 件** | — |
| `CCIE_MD5` | 3 件 | R62 の `authentication key-chain CCIE_MD5`（3412 / 3418 / 3424 行、Gi0/1・Gi0/2・Gi0/3 の af-interface 配下） |

つまり R62 は「**key chain を参照している行だけがあって、参照先の key chain 本体が無い**」という、意図的に穴を空けた状態でプリステージされている。
だからこそ Task 1.6 の R62 の解答は key chain の 3 行**だけ**（EIGRP ブロックは既に入っているので追加不要）。

この状態の R62 で `show key chain` を打つと何も出ないし、Gi0/1〜0/3 の EIGRP 隣接は認証キー不一致（というより鍵不在）で上がらない。
key chain を入れた瞬間に隣接が上がる、というのが Task 1.6 の実質的なゴール。

### そもそも `sh run | sec eigrp` では key chain は出ない

`| section` は「マッチした行から始まるコンフィグブロック」を切り出す機能。
key chain のブロックは

```
key chain CCIE_MD5
 key 1
  key-string CC!E!nfr4
```

で、どの行にも `eigrp` という文字列が無い。よって仮に key chain が設定済みの機器があっても、`sh run | sec eigrp` には**絶対に出てこない**。
確認したいときは用途別に打ち分ける:

| 目的 | コマンド |
|---|---|
| EIGRP プロセス設定を見る／コピペ元にする | `show run \| sec eigrp` |
| key chain が定義済みか見る | `show run \| sec key chain` |
| key の中身（key-string）を見る | `show run \| sec key chain`（`show key chain` は鍵名・有効期間中心） |
| 鍵が有効か（accept/send lifetime）を見る | `show key chain` |

### 一方で、コピペ戦略が効く範囲は思ったより広い

R62 の初期コンフィグには named mode のブロックが丸ごと入っている（EI_v2.yaml 3402〜3428 行）:

```ios
router eigrp ccie
 !
 address-family ipv4 unicast autonomous-system 65006
  !
  af-interface default
   passive-interface
  exit-af-interface
  !
  af-interface GigabitEthernet0/1
   authentication mode md5
   authentication key-chain CCIE_MD5
   no passive-interface
  exit-af-interface
  !
  af-interface GigabitEthernet0/2
   （同上）
  af-interface GigabitEthernet0/3
   （同上）
  !
  topology base
  exit-af-topology
  network 10.0.0.0
 exit-address-family
```

**R61 へはこれをそのまま貼れる。** R61 の LAN 側インターフェースは Gi0/1（→R62）・Gi0/2（→SW602）・Gi0/3（→SW601）で、
R62 の LAN 側（Gi0/1→R61、Gi0/2→SW601、Gi0/3→SW602）と**インターフェース番号の集合がまったく同じ**だから。
（接続先は入れ替わっているが、EIGRP を喋らせたい 3 本という点で一致する。WAN 側 Gi0/0・Gi0/4 を除外する点も同じ）

**SW601 / SW602 へ貼るときは af-interface の中身を差し替える必要がある。**

| 機器 | EIGRP を有効化する I/F | 備考 |
|---|---|---|
| R61 / R62 | Gi0/1, Gi0/2, Gi0/3 | Gi0/0（SP向けBGP）・Gi0/4（vrf WAN）は passive のまま |
| SW601 | Gi0/0, Gi0/1, Gi0/2, **vlan 2000, vlan 2001** | Gi0/0〜0/2 は `no switchport` のルーテッドポート、SVI 2 つが LAN サブネット |
| SW602 | Gi0/0, Gi0/1, Gi0/2, **vlan 2000, vlan 2001** | 同上 |

SVI の指定は `af-interface vlan 2000`（小文字 vlan + スペース + 番号）という書き方になる点が物理 I/F と違うので注意。

### 【前回キャッシュの訂正】SW601 / SW602 の初期コンフィグに EIGRP は一切ない

`Answers/pattern2/pattern2_q6.md` に「SW601/SW602 は af-interface が初期投入済みで `network 10.0.0.0` の追加だけでよい」と書いてあったが、
**これは誤り**。EI_v2.yaml の SW601（3711〜3757 行）・SW602（3842〜3888 行）の初期コンフィグを直接確認したところ、
両機とも `router eigrp` セクションそのものが存在しない。入っているのは以下だけ:

- `vlan 2000-2001`、`spanning-tree mode pvst`、`vtp mode transparent`
- Loopback0 / Gi0/0〜0/2（`no switchport` + /30 アドレス）/ Gi2/0（トランク）
- Vlan2000・Vlan2001 の SVI + HSRP（SW601 が `standby 100 priority 110` で Active）

したがって SW601 / SW602 は **key chain + EIGRP ブロック丸ごと**が候補者の作業（解答 HTML の記載どおり全量）。
Branch3 で「差分が key chain 3 行だけ」なのは R62 のみ。

### まとめ：Task 1.6 で本当に暗記が要るもの

| 項目 | 暗記要否 | 理由 |
|---|---|---|
| named mode のブロック構造（`address-family` / `af-interface` / `exit-af-interface`） | ほぼ不要 | R62 から `sh run \| sec eigrp` でコピペ可能 |
| `authentication mode md5` / `authentication key-chain <名前>` | ほぼ不要 | 同上（R62 に実物がある） |
| **`key chain` 3 行** | **必要** | ラボ内に実例が 0 件。要件文の値を自分で組み立てる |
| `network 10.0.0.0`（1 コマンドで全 LAN を広報という要件） | ほぼ不要 | R62 に実物がある |

key chain の 3 行は EIGRP 固有ではなく RIP / IS-IS / BFD 等でも共通の汎用構文なので、
`key chain 名前` → `key 番号` → `key-string 文字列` の 3 階層とだけ覚えておけばよい（key 番号は要件に指定がないので `1` でよい）。
IOS のヘルプ（`key chain ?` → `key ?` → `key-string ?`）でも辿れる。
