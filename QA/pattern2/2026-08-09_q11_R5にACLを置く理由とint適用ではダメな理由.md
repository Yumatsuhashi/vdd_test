# Task 1.11 「R5 で標準 ACL」がなぜ R5 なのか／なぜ BGP vrf fabd2 配下で、interface 適用ではダメなのか

## 質問

CCIE_train_hub/Questions/pattern2/pattern2_q11.md

R5で標準ACLを使用し、EIGRP以外の方法による広報を防止すること。　とあるがなぜR5なのか？
そしてなぜbgpのvrf fabd2でこれを実現しているのか？intに適用するなどではダメなのか

## 回答

### 対象 3 プレフィックスは全部 R24（DMVPN ハブ）自身のもの

| プレフィックス | 実体 |
|---|---|
| `10.2.114.0/30` | R24 Gi2 ↔ SW211 Gi1/0 |
| `10.2.214.0/30` | R24 Gi3 ↔ SW212 Gi1/0 |
| `10.2.255.24/32` | R24 Loopback0 |

問題文の `10.255.5.24/32` は**誤記**。R24 Lo0 は `10.2.255.24/32` で、解答 ACL も
`deny host 10.2.255.24`。ラボ上は `10.2.255.24/32` が正。

R24 の EIGRP は初期コンフィグで `network 10.2.0.0 0.0.255.255` を持つので、この 3 つは
すべて Tunnel0 経由でスポークへ流れる（`af-interface default / passive-interface` +
Task 1.11 で `af-interface Tunnel0 / no passive-interface`）。

## Q1. なぜ R5 なのか

### R61 だけ「MPLS 経路と EIGRP 経路が同じ RIB で衝突する」

スポーク 3 台の MPLS 側 PE-CE セッションの所在を初期コンフィグで比較すると、決定的な非対称がある。

| CE | 対向 PE | PE-CE セッションの所在（CE 側） | Tunnel0 / EIGRP の所在 | 同じ RIB？ |
|---|---|---|---|---|
| **R61** | R5 | `router bgp 65006` **直下＝グローバル**（`neighbor 100.5.61.1 remote-as 10000`）／ Gi0/0 100.5.61.2 も global | グローバル | **⚠️ 衝突する** |
| R70 | R6 | `address-family ipv4 vrf WAN`（`neighbor 100.6.70.1 remote-as 10000`）／ Gi0/0.100 は `vrf forwarding WAN` | グローバル | ✅ 別テーブルで衝突しない |
| R62 | R6 | グローバル直下（`neighbor 100.6.62.1 remote-as 10000`）＝衝突しうる | — | **問題文で「R62 は無視」** |

**R61 だけが、MPLS VPN から学習した経路と DMVPN/EIGRP の経路を同じグローバル RIB に持つ。**
R70 は MPLS 側が丸ごと VRF WAN に隔離されている（Gi0/0.100 が `vrf forwarding WAN`、
BGP neighbor も `af ipv4 vrf WAN` の中）ので競合しない。R62 は衝突しうるが問題文が明示的に除外している。

→ **R5 が唯一のフィルタ地点**になる。R6 側には何も打たない解答なのはこのため。

### 打たないとどうなるか — AD で eBGP が勝つ

| 経路源 | AD |
|---|---|
| eBGP（R5 → R61、MPLS 経由） | **20** |
| EIGRP internal（R24 → R61、Tunnel0 経由） | 90 |

R5 が 10.2.114.0/30 等を R61 へ広報すると、**AD 20 の eBGP が AD 90 の EIGRP を蹴散らす**。
R61 は DC 宛トラフィックを Gi0/0（MPLS 側）へ流し、DMVPN トンネルが使われなくなる。これは

- 「トンネルを介して、次のルートを広報するために EIGRP を使用すること」
- 「インターネットを通過するすべてのトラフィックを暗号化すること」

の両方に違反する。R5 で広報を止めて初めて、EIGRP 経路が唯一の経路として残る。

### 経路の対比図

```
             ┌─ MPLS L3VPN（プライベート・非暗号）────────────────┐
             │  R24 …DC… R21 ── R3(PE) ══ MP-BGP ══ R5(PE) ──┐  │
             │                                                │  │
   R24 ──────┤                                          eBGP AD20│
  (ハブ)      │                                                ▼  │
   10.2.114.0/30                                          R61 Gi0/0
   10.2.214.0/30                                          (global RIB)
   10.2.255.24/32                                              ▲
             │                                                 │
             └─ DMVPN over Internet（IPsec 暗号）              │
                R24 Gi1 ─ SP_1(AS19999) ─ R61 Gi0/4(vrf WAN)   │
                            Tunnel0 / EIGRP AS 65006 (AD 90) ──┘

   ★フィルタ無し → eBGP(20) が EIGRP(90) に勝ち、暗号化トンネルが未使用になる
   ★R5 で out フィルタ → MPLS 側の経路が消え、EIGRP 経路が唯一残る
```

## Q2. なぜ interface 適用ではダメか

### `ip access-group` はデータプレーン、要件は**コントロールプレーン**

問題文は「広報（advertisement）を防止」。止めたいのは **BGP UPDATE の中の NLRI**。

```
R5 → R61 に流れる BGP UPDATE パケット
  IP header : src 100.5.61.1 / dst 100.5.61.2   ← 標準 ACL が見るのはここだけ
  TCP 179
    payload : NLRI = 10.2.114.0/30, 10.2.214.0/30, 10.2.255.24/32  ← 止めたいのはココ
```

`ip access-group 66 out` を Gi1 に貼っても、UPDATE パケットの送信元/宛先は `100.5.61.x` なので
**ACL に一切マッチせず素通り**する。NLRI はペイロードの中身で、標準 ACL からは見えない。

### さらに悪いことに、I/F に貼るとブラックホールになる

経路広報が止まらないので、R61 の RIB には eBGP（AD 20）で 10.2.114.0/30 が**残ったまま**。

```
R61 の最適経路 : 10.2.114.0/30 via 100.5.61.1 (eBGP, AD 20)  ← 変わらない
                 ↓ パケットを Gi0/0 へ送出
R5 の Gi1 ACL でドロップ
                 ↓
結果 : 到達不能（ブラックホール）。DMVPN トンネルには切り替わらない
```

**経路そのものを RIB から消さないと最適経路は変わらない。** これが「フィルタは広報側でやる」理由。
データプレーンで落とすのは「通信を止める」対策であって「経路を切り替える」対策ではない。

### 正しい道具＝`neighbor <ip> distribute-list <acl> out`

このコマンドは ACL を「パケットのマッチ条件」ではなく **「プレフィックスのマッチ条件」** として使う。
標準 ACL の source フィールドがネットワークアドレスとして解釈され、**マスク長は見ない**
（`deny 10.2.114.0 0.0.0.3` は 10.2.114.0 で始まるネットワークにマッチ）。
厳密なマスク長比較が要るなら prefix-list だが、問題文が「標準 ACL」を指定している。

```ios
access-list 66 deny 10.2.114.0 0.0.0.3
access-list 66 deny 10.2.214.0 0.0.0.3
access-list 66 deny host 10.2.255.24
access-list 66 permit any            ! ★暗黙 deny any。これが無いと全経路が落ちる
!
router bgp 10000
 address-family ipv4 vrf fabd2
  neighbor 100.5.61.2 distribute-list 66 out
  neighbor 100.5.61.2 distribute-list 66 in
```

`in` も入っているのは対称性の保険（R61 側からこれらが VPN に入ってくるのも防ぐ）。
解答は 3 パターンとも in/out 両方ある。

### `address-family ipv4 vrf fabd2` に降りる理由は Task 1.10 と同じ

`neighbor 100.5.61.2` は R5 の**グローバル BGP には存在せず、VRF fabd2 の中にしかいない**。

```ios
! R5 初期コンフィグ（EI_v2.yaml）
router bgp 10000
 no bgp default ipv4-unicast
 neighbor 100.255.254.3 remote-as 10000      ← iBGP はグローバル
 …
 address-family ipv4 vrf fabd2
  redistribute connected
  neighbor 100.5.61.2 remote-as 65006        ← ★R61 はここにしか存在しない
  neighbor 100.5.61.2 activate
 exit-address-family
```

`distribute-list` は neighbor サブコマンドなので、その neighbor が定義された文脈に降りる必要がある。
グローバル直下で打つと `% Specify remote-as or peer-group commands first` になり、
remote-as から打つと**別人格の neighbor が無言で新規作成**されて何も効かない。
（詳細は `QA/pattern2/2026-08-07_q10_PE側だけaddress-family_ipv4_vrf配下に打つ理由.md`）

## 検証コマンド

```ios
! R5
show run | section router bgp                              ! neighbor の所在（context）確認
show ip bgp vpnv4 vrf fabd2 neighbors 100.5.61.2 advertised-routes | include 10.2.
                                                           ! ← 何も出ないこと
show ip access-lists 66                                    ! ヒットカウント

! R61（判定はここ一発）
show ip route 10.2.114.0                                   ! ★"D … via 10.200.0.1, Tunnel0" なら成功
                                                           !   "B … via 100.5.61.1" なら失敗
show ip eigrp topology 10.2.114.0/30
show ip bgp 10.2.114.0                                     ! BGP テーブルに無いこと
show dmvpn                                                 ! トンネル状態
```

判定は **R61 の `show ip route 10.2.114.0`** で付く。`D`（EIGRP）で Tunnel0 経由なら成功、
`B` なら R5 のフィルタが効いていない。

## 補足（Q9 と同種の注意）

Pattern 2 のラボでは、Task 1.5 の R21 に `no bgp redistribute-internal` があり、R21 の BGP は
`network 10.2.255.21/32` のみで DC LAN を MPLS VPN へ注入していない。したがって
**実機で `show ip bgp vpnv4 vrf fabd2` に 10.2.114.0/30 が現れない可能性がある**。
問題文の「**必要に応じて**、R5 で標準 ACL を使用し」という書き方はこれに対応しており、
解答は要件充足のための予防フィルタとして 3 パターン共通で入れている。
経路が見えないことを理由に設定を省いてはいけない。
