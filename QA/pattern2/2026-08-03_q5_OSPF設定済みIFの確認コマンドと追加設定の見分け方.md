# Pattern 2 Task 1.5 — OSPF 設定済みインターフェースの確認コマンドと「追加設定が必要な I/F」の見分け方

## 質問

SW101において
interface range GigabitEthernet0/0-1　これにしかospfの設定をしていないけど　問題文では「OSPFはすべてのインターフェースで有効化しなければならない」と書いてある　なぜSW101ではこのインターフェースだけに設定いらないとわかる？

SW201において設定していないのは事前設定されているからだと思うけどそれを確認するコマンドは？

## 回答

2 つの質問は**同じ 1 組のコマンドで両方とも答えが出る**。

### Q1. SW101 で Gi0/0-1 だけでいいと分かる根拠

前提の訂正: SW101 の解答は Gi0/0-1 だけではなく `interface range vlan 2000-2001` も設定している。

```ios
interface range vlan 2000-2001      ← こちらも設定している
 ip ospf 1 area 0
interface range GigabitEthernet0/0-1
 ip ospf 1 area 0
 ip ospf authentication message-digest
 ip ospf message-digest-key 1 md5 CC!E!nfr4
```

重要な点: **Gi0/0-1 の `ip ospf 1 area 0` は初期コンフィグに既に入っている**。

| インターフェース | 種別 | 初期コンフィグの OSPF | 追加設定 |
|---|---|---|---|
| Loopback0 (10.1.255.101) | L3 | `ip ospf 1 area 0` **済** | 不要 |
| Gi0/0 (10.1.10.2) → R11 Gi0/3 | L3 | `ip ospf 1 area 0` **済** | **MD5 認証のみ** |
| Gi0/1 (10.1.12.2) → R12 Gi0/2 | L3 | `ip ospf 1 area 0` **済** | **MD5 認証のみ** |
| Gi0/2 (10.2.241.2) → SW201 Gi1/2 | L3 | `ip ospf 1 area 0` **済** | 不要 |
| **Vlan2000 (10.1.100.2)** | L3 | **なし** | **`ip ospf 1 area 0` 追加** |
| **Vlan2001 (10.1.101.2)** | L3 | **なし** | **`ip ospf 1 area 0` 追加** |
| Gi1/2, Gi1/3 → SW110 | L2 trunk | — | 対象外（IP なし） |
| Gi2/0, Gi2/1 → SW102 | L2 trunk | — | 対象外 |
| Port-channel1, Port-channel3 | L2 trunk | — | 対象外 |

→ 「すべてのインターフェースで有効化」の観点で SW101 に足りなかったのは **Vlan2000/2001 だけ**。
Gi0/0-1 が解答に出ているのは OSPF 有効化のためではなく、要件「R11/R12 は対向ルータとの隣接を
MD5 認証で保護」への対応。OSPF の MD5 はリンク両端で鍵が一致しないとネイバーが落ちるため、
R11 Gi0/3 の対向である SW101 Gi0/0 にも同じ鍵が必要。解答の `ip ospf 1 area 0` は再入力しても
無害なので range にまとめて書かれているだけ。

判断根拠は 2 つに集約される:

1. **IP を持たない L2 スイッチポートには OSPF を乗せられない** → Gi1/2 以降は物理的に対象外
2. **初期コンフィグで既に `ip ospf 1 area 0` が入っているものは触らなくていい** → Lo0 / Gi0/0-2

Gi0/2 は L3 かつ OSPF 済みだが MD5 は不要。対向が SW201（DC 側）で R11/R12 ではないため要件の範囲外。

**Vlan2000/2001 を入れ忘れると**: 10.1.100.0/24 と 10.1.101.0/24 が OSPF に広報されず、DC 側から
ユーザー VLAN に戻れない。問題4 の DHCP リレー（サーバ 10.2.255.211 → giaddr 10.1.100.2 宛の応答）
も返ってこなくなる（[[2026-08-03_q4_HSRP仮想IPがデフォルトGWである理由とhelper-addressの役割]] と接続）。

### Q2. 「設定済み」を確認するコマンド

本番で使うのは**この 2 つの差分**:

```ios
show ip interface brief | exclude unassigned    ← IP を持つ（＝L3 の）インターフェース一覧
show ip ospf interface brief                    ← OSPF が有効なインターフェース一覧
```

**前者にあって後者に無いもの = これから設定が必要なインターフェース。**

SW201 で `show ip ospf interface brief` を打つと初期コンフィグ由来で以下が全部並ぶ:

```
Interface  PID  Area  IP Address/Mask     Cost  State Nbrs F/C
Lo0        1    0     10.2.255.201/32     1     LOOP  0/0
Gi0/0      1    0     10.2.10.2/30        1     P2P   1/1
Gi0/1      1    0     10.2.12.2/30        1     P2P   1/1
Gi0/3      1    0     10.2.109.1/30       1     ...
Gi1/0      1    0     10.2.23.1/30        1     ...
Gi1/1      1    0     10.2.20.1/30        1     ...
Gi1/2      1    0     10.2.241.1/30       1     ...
Vl3999     1    0     10.2.201.11/29      1     ...
Vl4000     1    0     10.2.201.3/29       1     ...
```

L3 インターフェースが全部揃っている（残る Gi0/2 と Gi1/3 は trunk なので IP なし）→ SW201 は追加設定ゼロ。

同じことを SW101 でやると `show ip interface brief` には Vlan2000/Vlan2001 が出るのに
`show ip ospf interface brief` には出てこない → **差分がそのまま解答**になる。

#### 罠: `show run | section router ospf` だけ見ると空に見える

このラボは `network` 文ではなく**インターフェース直付け方式**（`ip ospf 1 area 0`）。
SW101/SW201 とも `router ospf 1` の下は空っぽなので、そこだけ見て「未設定だ」と誤判定しないこと。

#### 補助コマンド

| コマンド | 分かること |
|---|---|
| `show ip protocols` | `Routing Protocol is "ospf 1"` / Router ID / **Routing on Interfaces Configured Explicitly (Area 0)** の一覧（直付け方式でもここに出る） |
| `show ip ospf neighbor` | 隣接が実際に FULL か（設定済みの最終証拠） |
| `show ip ospf interface Gi0/0` | そのポートの area・cost・**認証方式**（`Message digest authentication enabled` / `Youngest key id is 1`） |
| `show run interface Vlan2000` | 個別インターフェースの生 config |
| `show ip ospf database` | 該当サブネットの LSA が実際に流れているか |

MD5 認証の有無は `show ip ospf interface brief` には出ない。認証だけは `show ip ospf interface <if>`
または `show run interface <if>` で確認する。
