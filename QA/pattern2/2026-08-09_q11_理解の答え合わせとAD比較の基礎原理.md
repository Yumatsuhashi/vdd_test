# Task 1.11 理解の答え合わせ（Branch3 は OSPF ではなく EIGRP／横取りするのは SP1 側ではなく R5 側）と AD 比較の基礎原理

## 質問

- Branch3では
    - 内部のルーティングとしてOSPF
    - R61がSP1(インターネット)とBGP as 6501で接続
        - R61→SP1→R24と繋がっている
- DMVPNを使用する際にR61→SP1→R24の経路で張って、eigrpでルーティングしたい
- しかし eBGPのAD値が20なため、R61→SP→R24を経由してしまう
- そのためeBGPよりeigrpを使ってもらう設定が必要
ここまで正しい？

またAD値を比較する際の基礎原理がわからないから手順を追って説明して欲しい

## 回答

### 認識のチェック（3 か所修正）

#### ❌ 1. 「Branch3 の内部ルーティングは OSPF」→ **EIGRP**

Task 1.6（サイト内ルーティング BR3）は **EIGRP 名前付きモード（AS 65006）**。
R61 の初期コンフィグに `router ospf` は **0 行**。

```ios
! Task 1.6 で R61 に入れる
router eigrp ccie
 address-family ipv4 unicast autonomous-system 65006
  af-interface GigabitEthernet0/1   ! → R62
   authentication mode md5
   authentication key-chain CCIE_MD5
   no passive-interface
  af-interface GigabitEthernet0/2   ! → SW602
  af-interface GigabitEthernet0/3   ! → SW601
  network 10.0.0.0
```

OSPF は **HQ と DC** の中（Task 1.5）。Branch 3 は EIGRP。

**Branch 3 内部の IGP と DMVPN トンネルの中の IGP は、どちらも同じ EIGRP AS 65006**。別物ではない。

#### ⚠️ 2. 「R61 が SP1 と BGP AS 6501 で接続」→ AS 番号と所在が違う

```ios
! R61 初期コンフィグ
router bgp 65006                          ← R61 自身の AS は 65006（6501 ではない）
 neighbor 100.5.61.1 remote-as 10000      ← ★R5 (MPLS) 向け。グローバル
 !
 address-family ipv4 vrf WAN
  neighbor 200.99.61.1 remote-as 19999    ← SP1 (インターネット) 向け。VRF WAN の中
```

R61 は **BGP セッションを 2 本**持つ。これが混同の元。

| セッション | 相手 | 相手の AS | 所在 | 受け取るもの |
|---|---|---|---|---|
| ① | **R5**（MPLS の PE） | 10000 | **グローバル** | 他拠点の具体的な経路 |
| ② | **SP1**（インターネット） | 19999 | **VRF WAN** | **デフォルトルート `0.0.0.0/0` だけ** |

#### ❌ 3. 一番大事な誤解：横取りするのは SP1 側ではない

> しかし eBGP の AD 値が 20 なため、R61→SP→R24 を経由してしまう

**逆**。`R61 → SP1 → R24` は**使いたい方（正解の道）**。
横取りするのは **① の R5 経由（MPLS）**。

```
   ★横取りする悪者（消したい）
   R61 ─ R5 ─ [MPLS コア R1/R2] ─ R3 ─ R21 ─ DC ─ R24
        eBGP AD 20 / グローバル・テーブル / 暗号化なし

   ★使いたい正解（残したい）
   R61 ─ SP1(インターネット) ─ R24     ← この上に DMVPN トンネル
        トンネルの中で EIGRP AD 90 / グローバル・テーブル / IPsec 暗号化
```

**② の SP1 セッションは競合しない**。理由が 2 つ:

1. **箱が違う** — ② は VRF WAN、EIGRP 経路はグローバル
2. **プレフィックスが違う** — ② が運ぶのは `0.0.0.0/0` だけ。`10.2.114.0/30` とは別エントリで比較対象にならない

#### ⚠️ 4. 「eBGP より EIGRP を使ってもらう設定」→ 方向は合っているが手段が違う

AD を書き換える（`distance` コマンド）のではなく、**R5 で BGP 経路そのものを消す**。

| やり方 | 何をする | 今回の解答 |
|---|---|---|
| AD を変える | R61 で `distance bgp 200 200 200` 等 | ✗ 使わない |
| **経路を消す** | R5 で `distribute-list 66 out` して広報しない | **✓ こちら** |

問題文が「R5 で標準 ACL を使用し」と場所も道具も指定しているため。

### 修正版の理解

```
- Branch3 の内部ルーティングは EIGRP 名前付きモード（AS 65006）
- R61 は BGP セッションを2本持つ
    - ① R5 (AS 10000) とグローバルで接続 … MPLS L3VPN。他拠点の経路が入る
    - ② SP1 (AS 19999) と VRF WAN で接続 … インターネット。デフォルトルートだけ受信
- DMVPN は ② の回線の上に張る（R61 Gi0/4 → SP1 → R24 Gi1）。中で EIGRP AS 65006 を流す
- しかし ① の eBGP (AD 20) が EIGRP (AD 90) に勝ってしまい、
  DC 宛のトラフィックが暗号化されない MPLS 側へ流れてしまう
- そこで ① の入口である R5 で、該当3プレフィックスの広報を止める（ACL 66 + distribute-list）
```

## AD 比較の基礎原理（手順を追って）

### 大前提：RIB は 1 つの宛先に 1 本しか置けない

`show ip route` に出るのは「勝った 1 本」だけ。負けた経路は消滅するのではなく、
**各プロトコルのデータベースには残る**（`show ip bgp` / `show ip eigrp topology` では見える）。

### Step 1：各プロトコルが「自分の中で」最良経路を 1 本選ぶ

この段階では **AD は一切登場しない**。プロトコルごとに独自のルールで選ぶ。

| プロトコル | 選び方 |
|---|---|
| BGP | ベストパス選択（Weight → Local Pref → AS Path 長 → Origin → MED → …） |
| EIGRP | DUAL（FD が最小の Successor） |
| OSPF | SPF（コスト最小） |

R61 の例:
- BGP は「10.2.114.0/30 は via 100.5.61.1 が最良」と決める
- EIGRP は「10.2.114.0/30 は via 10.200.0.1 (Tunnel0) が最良」と決める

### Step 2：各プロトコルが RIB に「候補」を提出する

```
   BGP プロセス ──「10.2.114.0/30 via 100.5.61.1、私の AD は 20 です」──┐
                                                                        ├→ RIB
   EIGRP プロセス ─「10.2.114.0/30 via 10.200.0.1、私の AD は 90 です」─┘
```

### Step 3：RIB が AD を比べる（小さい方が勝ち）

```
   AD 20  (eBGP)   ← 勝ち。RIB に載る
   AD 90  (EIGRP)  ← 負け。RIB には載らない
```

AD は「その経路源をどれだけ信用するか」の**信用度の順位**。**数字が小さいほど信用が高い**という約束。

| 経路源 | AD |
|---|---|
| Connected（直結） | **0** |
| Static | 1 |
| EIGRP summary | 5 |
| **eBGP** | **20** |
| **EIGRP internal** | **90** |
| OSPF | 110 |
| IS-IS | 115 |
| RIP | 120 |
| EIGRP external（再配布された経路） | 170 |
| iBGP | 200 |
| unreachable | 255 |

### Step 4：AD が同点なら初めてメトリックを見る

**プロトコルが違うとメトリックは比較できない**（EIGRP の帯域ベースの値と BGP の AS パス長は単位が違う）。
だから先に AD で決着をつけ、**同じプロトコル内（＝AD が同じ）でのみメトリックを比較**する。

```
AD が違う  → AD だけで決着。メトリックは見ない
AD が同じ  → メトリック（EIGRP の FD、OSPF のコスト等）で決着
両方同じ   → ECMP（両方 RIB に載せて負荷分散）
```

### 必ず押さえる 4 つの原則

| # | 原則 | 具体例 |
|---|---|---|
| **A** | AD 比較は「**プレフィックス＋マスク長が完全に一致**」した時だけ起きる | `10.2.114.0/30` と `0.0.0.0/0` は競合しない。**両方 RIB に共存**し、転送時は longest match で /30 が使われる |
| **B** | AD 比較は「**同じルーティングテーブル（VRF）の中**」でのみ起きる | R70 は BGP が VRF WAN・EIGRP がグローバルなので、同じ /30 でも比較されない |
| **C** | AD は**そのルータの中だけの値**。隣のルータには広告されない | R5 で AD を変えても R61 には伝わらない |
| **D** | 負けた経路は**プロトコルのデータベースには残る** | `show ip bgp` には出るが `show ip route` には出ない |

**原則 A** が SP1 のデフォルトルートが競合しない理由。**原則 B** が R70 にフィルタ不要の理由。

### R61 での具体的な流れ

```
【フィルタなし】
  BGP  : 10.2.114.0/30 via 100.5.61.1   AD 20  ─┐
  EIGRP: 10.2.114.0/30 via 10.200.0.1   AD 90  ─┴→ RIB は AD 20 を採用

  R61# show ip route 10.2.114.0
  B    10.2.114.0/30 [20/0] via 100.5.61.1     ← ✗ MPLS 経由（非暗号）

【R5 で distribute-list 66 out】
  BGP  : （そもそも広報されないので候補が存在しない）
  EIGRP: 10.2.114.0/30 via 10.200.0.1   AD 90  ──→ RIB は EIGRP を採用（無投票当選）

  R61# show ip route 10.2.114.0
  D    10.2.114.0/30 [90/26880] via 10.200.0.1, Tunnel0   ← ✓ DMVPN 経由（暗号化）
```

`0.0.0.0/0`（SP1 から VRF WAN で受信）は**この争いに参加しない**。
原則 A（マスク長が違う）と原則 B（VRF が違う）の両方で対象外。
