# Task 1.8 を本番で最短で解く動き方（コピペ前提・4ブロックのみ／Task 1.7 が絶対前提／問題文 80,000 と解答資料 90 の矛盾／R1・R2 は作業ゼロ）

## 質問

```
q8についてもコピペが可能なことを前提として最短の解き方を考えてまとめて
```

## 回答

### 🔴 前提 1: Task 1.7 を先に終わらせないと iBGP は絶対に上がらない

R3 と R5 の **Loopback0 は初期コンフィグで OSPF に入っていない**（R5 は OSPF プロセス自体が無い）。
iBGP は全て `update-source Loopback0` なので、**1.7 を飛ばして 1.8 をやると全 iBGP が Idle のまま**になる。
config は完璧なのに動かないという最悪の時間の溶かし方をする。

さらに VPNv4 の next-hop 解決には LDP ラベルが要るので、**1.7 は二重の意味で前提**。

> **1.8 に着手する前に、R1 で `sh ip ospf nei` が 3 行出ることだけ確認する。**

---

### 🔴 前提 2: 問題文の「80,000」と解答資料の「90」が矛盾している

問題文（`Questions/pattern2/pattern2_q8.md`）:
> - 受信プレフィックス数が **80,000を超えた場合**、警告メッセージを生成すること
> - **100,000を超えた場合**、該当するBGPセッションをシャットダウンすること
> - **5分後に自動的に再確立**されること

`maximum-prefix <上限> <警告閾値%> restart <分>` の第 2 引数は**パーセント**。

| config | 警告が出る本数 | 問題文と一致？ |
|---|---|---|
| `maximum-prefix 100000 **80** restart 5` | 80,000 | ✅ |
| `maximum-prefix 100000 **90** restart 5` | 90,000 | ❌ |

手元の解答資料は 3 箇所すべて `90`（RS 比較 HTML 1346 / 3768 行、Pattern 4 チートシート 2124 行）だが、
**問題文どおりなら `80` が正解**。本番では問題文の数字が正なので、当日の問題文を読んで決める。

（同種の資料ブレ: パスワードも問題文 `CCIE!nfr4` に対し解答 HTML は `CC!E!nfr4`。Q7 と同じ罠。**問題文が正**）

---

### 結論: 貼るのは 4 ブロックだけ。R1/R2 は作業ゼロ

問題文「R1およびR2では、BGPを動作させてはならない」→ 初期コンフィグに BGP が 1 行も無いので**確認すら不要**。

| 機器 | 作業量 | 内容 |
|---|---|---|
| **R3** | **大（唯一のゼロ構築）** | vrf / interface / bgp すべて新規 |
| R4 | 小 | RT 修正 + password 3 行 |
| R5 | 小 | RT + password 3 行 |
| R6 | 小 | RT + password 3 行 |
| R1/R2 | **なし** | BGP 禁止 = 初期状態のまま |

---

### 貼る順番: R3 → R4 → R5 → R6

R3 を先頭にする理由は 2 つ:

1. **唯一ミスしうるブロックを、頭がフレッシュなうちに終わらせる**（`vrf forwarding` の IP 消失）
2. **即座に成功シグナルが出る** — PE-CE の eBGP には password が付かず、CE 側（R11/R21）は初期設定済みなので、
   **R3 を貼った瞬間に eBGP 2 本が Established になる**。VRF とインタフェースが正しいことがその場で確認できる

R4〜R6 の間の順序は**どうでもいい**。MD5 は両端が揃うまでセッションが落ちるが、揃えば自動復旧する。
Task 1.7 の `mpls ldp password required`（未認証を恒久拒否）と違い、
**BGP の MD5 は途中経過が汚いだけで最終状態は変わらない**。途中のログに動揺しないこと。

### 事前設定の非対称性（なぜ R3 だけ巨大か）

| PE | `vrf definition` | I/F の `vrf forwarding` | `router bgp` | 初期 RT |
|---|---|---|---|---|
| **R3** | **なし** | **なし**（Gi1/Gi2 は global に IP 済） | **なし** | — |
| R4 | あり（rd 10000:4） | なし（IaaS 向けなので不要） | あり（iBGP vpnv4 のみ） | **10000:4** ← 唯一の要修正 |
| R5 | あり（rd 10000:5） | あり（Gi1） | あり（eBGP まで完成） | 10000:1 |
| R6 | あり（rd 10000:6） | あり（Gi1, Gi2.100） | あり（eBGP まで完成） | 10000:1 |

**R4 に `address-family ipv4 vrf fabd2` が無いのは正常。**
問題文の「IaaSサイトは、このタスクの対象に含まれない」がその理由で、
R4 の CE 向け（Gi1.100 / Gi1.414 = 100.4.30.x）は IaaS 拠点行き。
CML ラボでも R4 の物理リンクは `R4-Gi8<->R2-Gi0/1` の 1 本しか存在しない。
**「R4 だけ eBGP が無い＝設定漏れ」と誤認しないこと。**

ピア数の内訳: R3 = iBGP3 + eBGP2 = **5**、R6 = iBGP3 + eBGP2 = **5**、R5 = iBGP3 + eBGP1 = 4、R4 = iBGP3 のみ = 3。
問題文が 5 本を要求しているのは R3 と R6 だけで、これと整合する。

### 罠 4 つ（テンプレが自動で潰す）

| 罠 | 実態 | 対処 |
|---|---|---|
| **`vrf forwarding` で IP が消える** | `% IPv4 disabled and address(es) removed` が出る。順序ミスで R3 の Gi1/Gi2 が無アドレスに | ブロック内で `vrf forwarding` → `ip address` を隣接配置済み |
| **RT と RD の混同** | R3 は `rd 10000:3` なのに `route-target 10000:1`。この非対称が**正しい** | ブロックに直書き |
| **maximum-prefix の全角スペース** | 解答 HTML のこの行は行頭が U+3000。貼ると構文エラー | 上のブロックは半角に修正済み |
| **`80` か `90` か** | 問題文 80,000 → `80`。資料は全て `90` | **当日の問題文の数字を読む** |

### 検証: 3 台・5 コマンド（約 1 分）

password 変更直後はセッションが再接続タイマー待ちになるので、
**R3 で `clear bgp all *` を 1 回打ってから**検証すると待ち時間が消える。

```
! R3 で（本命）
clear bgp all *
sh bgp all summary                   → 5 セッション全て Established
                                        （.4/.5/.6 の iBGP + 100.3.11.2/100.3.21.2 の eBGP）
sh ip route vrf fabd2 | i ^B         → 他拠点の経路が入っている
                                        ★これが通れば RT 10000:1 の全台整合が同時に証明される
sh ip bgp neighbors 100.3.21.2 | i prefix   → maximum-prefix の値確認

! R4 で（唯一 RT を書き換えた台）
sh vrf detail fabd2 | i Import|Export   → 10000:1 のみ。10000:4 が消えていること

! R6 で（要件「ピア5つ」の対象）
sh bgp all summary                   → 5 セッション全て Established
```

#### 検証を減らせる根拠

- **`sh bgp all summary` が Established = MD5 が正しい証明**（不一致ならセッションが上がらない）。
  password を個別に確認するコマンドは不要。
- **R3 の VRF テーブルに R4/R5/R6 由来の経路が入っていれば、4 台の RT が揃っている証明**。
  `show vrf detail` を 4 台分見る必要はない（R4 だけは書き換えた台なので念のため確認）。

---

### 補足: 「すべての BGP セッションを保護」の範囲

問題文は「**Global SP #1 内の**すべての BGP セッション」。
CE（R11/R21/R61/R62/R70）は SP #1 の外なので、**password は PE 間 iBGP の 6 本のみ**。
PE-CE の eBGP に付けると CE 側が未設定なのでセッションが落ちる。解答も iBGP にしか付けていない。

---

### 所要時間の目安

準備済みなら **貼り 4 回で約 90 秒 + 検証 1 分 = 2 分半**。
本番で頭を使うのは「**1.7 が終わっているか**」と「**80 か 90 か**」の 2 点だけ。
