# Task 1.11 `ip nhrp map 10.200.0.1 200.99.24.2` の 2 つの IP の意味と、本番でどこから確認するか

## 質問

R61のip nhrp map 10.200.0.1 200.99.24.2　のIPが何を示しているのかわからない　またこのIPはどこから確認できるのかわからない

## 回答

### 前提：トポロジ図に IP は書かれていない

`topology2.png` は **インターフェース名だけ**（`G0/4`, `G1` 等）で IP アドレスの記載がない。
したがって IP は必ず機器から拾う。

### そもそもこの行は何のためにあるか

R61 の Tunnel0 には **`tunnel destination` が無い**（`tunnel mode gre multipoint`）。

- **普通の GRE（p2p）**: `tunnel destination 200.99.24.2` と 1 行書けば終わり。宛先が 1 個に固定
- **mGRE（DMVPN）**: 相手が複数いるので destination を書けない
  → **「この相手にはこの住所」という対応表**が別途必要

その対応表が NHRP。**`ip nhrp map` は mGRE で `tunnel destination` が書けないことの埋め合わせ**。

### 2 つの IP の意味 —— ARP と同じ構造

```
arp         10.1.1.1      0011.2233.4455   ← IP  → MAC
ip nhrp map 10.200.0.1    200.99.24.2      ← 論理 → 物理
```

**左が論理（トンネルの中での名前）、右が物理（実際に届ける住所）**。ARP と同じで論理が先、物理が後。

| | 値 | 意味 |
|---|---|---|
| 第1引数 | `10.200.0.1` | R24 の **Tunnel0** の IP。トンネルの中でのハブの名前 |
| 第2引数 | `200.99.24.2` | R24 の **Gi1** の IP。インターネット上でハブに届く実住所（NBMA） |

R61 が `10.200.0.1` 宛にパケットを出すとき、**外側の GRE ヘッダの宛先に何を書けばいいか**を教えている行。

---

## 本番でどこから確認するか

### ① `10.200.0.1` → R61 自身の config に既に書いてある

```
R61# show run interface Tunnel0
interface Tunnel0
 ip address 10.200.0.61 255.255.255.0   ← 自分は .61、/24 なので仲間は 10.200.0.0/24
 ip nhrp map multicast 10.2.255.24
 ip nhrp map 10.2.255.24 10.200.0.1
 ip nhrp nhs 10.200.0.1                 ← ★ここ。ハブ（NHS）は 10.200.0.1
 ip nhrp network-id 1010
 tunnel source Loopback0
 tunnel mode gre multipoint
 tunnel protection ipsec profile prof
```

**`ip nhrp nhs` の値がそのまま map の第1引数**。自分で考える必要はなく既存の値を持ってくるだけ。
`ip nhrp nhs` ＝「NHS（＝ハブ）はトンネル上のどこに居るか」なので当然同じ値になる。

### ② `200.99.24.2` → R24 にログインして見る

R61 の中には**どこにも書かれていない**。R24 側で確認する。

```
R24# show ip interface brief | include GigabitEthernet1
GigabitEthernet1    200.99.24.2   YES manual up    up     ← ★ここ
```

問題文が「**R24は、IPsecピアとの接続に GigabitEthernet1 を使用すること**」と I/F を名指ししているので、
迷う余地なく「R24 の Gi1 を見に行く」が正解ルート。R24 はそもそも自分で設定する対象機なので必ずログインする。

**検算に使えるアドレス規則**（推測の根拠にはせず確認後の答え合わせに使う）:

```
200.99.<機器番号>.0/30    ISP 側が .1、ブランチ側が .2
  R24 → 200.99.24.2   R61 → 200.99.61.2   R70 → 200.99.70.2   R62 → 200.99.62.2
```

自分が `200.99.61.2` なのを `show ip int brief` で見れば規則には気づける。

### ⚠️ ルーティングテーブル・CDP からは絶対に分からない

SP_1 の BGP:

```
router bgp 19999
 redistribute static             ← static だけ。connected は広報しない
 default-information originate
!
ip route 0.0.0.0 0.0.0.0 Null0
```

**R61 が受け取るのは `0.0.0.0/0` の 1 本だけ。** `show ip route vrf WAN` を叩いても
`200.99.24.0/30` は出てこない。
CDP も使えない（R61 Gi0/4 の隣は SP_1 で、R24 は 2 ホップ先）。

**「R24 の Gi1 を直接見に行く」以外に確認方法はない。**

---

## 設定後の確認 —— 対応表がそのまま見える

```
R61# show ip nhrp
10.200.0.1/32 via 10.200.0.1
   Tunnel0 created 00:01:23, never expire
   Type: static, Flags: used
   NBMA address: 200.99.24.2        ← ★打った 2 つの IP がこう並ぶ
```

```
R61# show dmvpn
   Peer NBMA Addr    Peer Tunnel Add   State
   200.99.24.2       10.200.0.1        UP
   （物理）          （論理）
```

`show dmvpn` は **config と左右が逆順**（NBMA が先）で表示されるので注意。

## まとめ

| 値 | 出どころ | コマンド |
|---|---|---|
| `10.200.0.1` | **R61 の既存 config** | `show run interface Tunnel0` の `ip nhrp nhs` 行 |
| `200.99.24.2` | **R24 の物理 I/F** | R24 で `show ip interface brief`（問題文が Gi1 と名指し） |

**「トンネル側の値は自分の config から、物理側の値は相手機から」**——この 2 系統で拾う。
