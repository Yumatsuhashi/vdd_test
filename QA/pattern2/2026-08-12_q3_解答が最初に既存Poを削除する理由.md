# Task 1.3 解答が最初に `no interface port-channel N` で既存 Po を壊す理由

## 質問

CCIE_train_hub/Questions/pattern2/pattern2_q3.md
この問題の回答で最初に既存の po を破壊しているけどそれはなぜ？

## 回答

理由は4つあり、すべて **「初期コンフィグに Po が中途半端な状態で残っている」** ことに起因する。

### 初期状態の棚卸し（`EI_v2.yaml`）

| 機器 | Po 論理IF | Po の初期設定 | メンバー物理 | `channel-group` |
|---|---|---|---|---|
| SW101 | Po1 | trunk/dot1q・**allowed vlan 指定なし** | Gi1/2-3 | **無し（＝メンバーゼロの空Po）** |
| SW101 | Po3 | trunk/dot1q・allowed vlan 指定なし | Gi2/0-1 | `mode active` |
| SW102 | Po2 | 同上 | Gi1/2-3 | `mode passive` |
| SW102 | Po3 | 同上 | Gi2/0-1 | `mode active` |
| SW110 | Po1 | 同上 | Gi1/0-1 | **`mode on`（LACPでない）** |
| SW110 | Po2 | 同上 | Gi1/2-3 | `mode passive` |

**Po ごとに壊れ方が全部違う**のがポイント。

---

### 理由① 互換性チェックに引っかかって bundle できない（本命）

EtherChannel には互換性チェックがあり、メンバー物理ポートと Po の間で以下が一致していないとバンドルされない:

- switchport mode（access / trunk）
- trunk encapsulation
- **allowed VLAN リスト** ← ここが効く
- native VLAN
- speed / duplex
- STP のポートコスト・プライオリティ

初期の `Port-channel1` は `switchport trunk allowed vlan` が無い＝**許可 VLAN は `1-4094`**。
この Po を残したまま物理側に打つと:

```
SW101(config)# interface range Gi1/2-3
SW101(config-if-range)# switchport trunk allowed vlan 1,2000,2001
SW101(config-if-range)# channel-group 1 mode active

%EC-5-CANNOT_BUNDLE2: Gi1/2 is not compatible with Po1 and will be
  suspended (trunk vlans allowed mismatch)
```

→ メンバーが `(s) suspended` になり **Po1 は上がらない**。
Task 1.3 の EtherChannel 要件も、Task 1.2 の「Po1 でタグ付き転送」要件も両方落ちる。

**Po を先に消しておけば、`channel-group 1 mode active` を打った瞬間に Po1 が自動生成され、
物理ポートの設定（allowed vlan 込み）がそのまま Po にコピーされる**ので不一致が起きない。
これが「Po を消して物理側から作り直す」の核心。

### 理由② `no interface port-channel N` はメンバーの `channel-group` 行も一緒に消す

Po を削除すると、メンバー物理ポートに残っていた `channel-group N mode xxx` も外れる。これにより

- SW110 Gi1/0-1 の `mode on`
- SW102 Gi1/2-3 / SW110 Gi1/2-3 の `mode passive`

が一括でクリアされ、**全機器・全 Po をまったく同じ手順で作り直せる**。
特に `mode on` → `mode active` はメンバーシップを外さずに直接切り替えようとすると素直に通らないので、
Po ごと消すのが一撃で確実。

> 削除後は `show run | section ^interface GigabitEthernet1/` で `channel-group` が本当に消えているか確認しておくと安全。

### 理由③ 要件が「802.3ad」＝ LACP なので `mode on` は失格

- `mode on` は LACP を喋らない静的バンドル。`show etherchannel summary` の Protocol 欄が `-` になる
- `passive ↔ passive` はどちらも LACPDU を能動的に送らないので永久にバンドルしない（SW102 Po2 ↔ SW110 Po2 がこれ）

→ 全リンクを `active` に統一する必要があり、その最短で事故らない手段が「消して作り直す」。

### 理由④ 解答の並び順がそれを裏付けている

SW101 の解答:

```
no interface port-channel 1                       ← ①消す
no interface port-channel 3
!
interface range GigabitEthernet1/2-3              ← ②物理から再生成（Poが自動で生まれる）
 switchport
 switchport trunk encapsulation dot1q
 switchport mode trunk
 switchport trunk allowed vlan 1,2000,2001
 channel-group 1 mode active
 no shutdown
...
interface range port-channel 1, port-channel 3    ← ③生まれ直したPoに設定を載せ直す
 spanning-tree guard root
```

Po を消すと Po に付いていた設定も全部消えるので、**root guard は再生成の後に打ち直す**構成になっている。
「消す → 物理 → Po」という順序自体がこの設計の証拠。

---

### 別解: 消さずにやることもできる

Po インターフェースに打った `switchport` 系設定は**メンバー物理ポートへ伝播する**ので、次でも成立する:

```
interface Port-channel1
 switchport trunk allowed vlan 1,2000,2001     ← Po側を先に合わせる
!
interface range GigabitEthernet1/0-1
 no channel-group 1                            ← mode on を一旦外す
 channel-group 1 mode active
```

ただし機器ごとに壊れ方が違う（SW101 Po1 は空、SW110 Po1 は `on`、Po2 は `passive`…）ため、
**手順が Po ごとにバラバラになる**。3パターン共通で同じ書き方にできる「消して作り直す」の方が、
本番でのテンプレートとして優れている。

### 注意点

- `no interface port-channel N` を打った瞬間に**リンクが落ちる**（Task 1.2 で通した VLAN 2000/2001 の転送も一時停止）。本番では通信断を織り込む
- 消した直後に物理ポート設定を打ち忘れると、トランクどころか**素の access VLAN 1 ポート**に戻る。連続して打ち切ること
- **順序厳守**: 消す → 物理（`switchport` 系 + `channel-group` + `no shutdown`）→ Po（`spanning-tree guard root`）
- SW101 Po3 / SW102 Po3 は初期から `mode active` 同士で**既にバンドル成立済み**。それでも消すのは allowed vlan を絞るためと、手順を統一するため

### 事後確認

```
show etherchannel summary        ← Po が (SU)、Protocol が LACP、全メンバーが (P)
show lacp neighbor               ← 対向が見えているか
show interfaces trunk            ← Vlans allowed on trunk が 1,2000-2001
show run | section ^interface Port-channel
```
