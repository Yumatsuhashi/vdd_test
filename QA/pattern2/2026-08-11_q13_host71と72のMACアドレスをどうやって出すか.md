# Task 1.13 host71 / host72 の MAC アドレスをどうやって出すか（IP が無いように見える件も含む）

## 質問

host71とhost72にはIPアドレスもないしMACアドレスもないのですがどうやてmacアドレスが出るようにする？

## 回答

### 事実確認：両方とも IP は設定されている

`EI_v2.yaml` の実際の値:

| ノード | 種別 | インターフェース | IP |
|---|---|---|---|
| host71 | `iol-xe`（**IOL の Cisco ルータ**） | `Ethernet0/0` | **192.168.0.123/24** |
| host72 | `iol-xe` | `Ethernet0/0` | **172.31.70.123/24** |

「IP がない」と見えるなら、**インターフェース名が `Ethernet0/0`**（`GigabitEthernet` ではない）
ことが原因の可能性が高い。IOL は Et0/0〜Et0/3 を持ち **Et0/1〜0/3 は unassigned** なので、
見る行を間違えると「IP なし」に見える。

```
host71# show ip interface brief
Interface       IP-Address       OK? Method Status   Protocol
Ethernet0/0     192.168.0.123    YES manual up       up        ← ここ
Ethernet0/1     unassigned       YES unset  admin down down
Ethernet0/2     unassigned       YES unset  admin down down
```

本当に空ならノードが起動していないか day0 コンフィグが未適用。

### MAC アドレスは「設定するもの」ではない

**IP の有無と MAC の有無は無関係。** MAC はインターフェースのハードウェアに焼かれている値で、
IP が 1 つも無くても `shutdown` されていても必ず存在する。コマンドで作るものではない。

```
host71# show interfaces Ethernet0/0 | include address is
  Hardware is iol, address is aabb.cc00.7100 (bia aabb.cc00.7100)
                              ^^^^^^^^^^^^^^ これが答え
```

**IP が無くても必ず動く。一番確実な取得法。**

---

### 本命は R70 から ping する方法

host71/72 のゲートウェイは **R70** で、SW700 のトランク越しに繋がっている。

```
R70 Gi0/2.100 (dot1q 100, vrf WAN)   ─┐
                                       ├─ Gi2/1 [SW700] Gi0/0 ─ host71 (VLAN 100)
R70 Gi0/2.414 (dot1q 414, vrf kiosk) ─┘   (trunk)      Gi0/1 ─ host72 (VLAN 414)
```

R70 から ping すれば **MAC の取得と SW700 への学習が同時に起きる。**

```
R70# ping vrf WAN   192.168.0.123        ← host71
R70# ping vrf kiosk 172.31.70.123        ← host72

R70# show ip arp vrf WAN   | include 192.168.0.123
Internet  192.168.0.123   0   aabb.cc00.7100  ARPA  GigabitEthernet0/2.100
R70# show ip arp vrf kiosk | include 172.31.70.123
```

**⚠️ VRF 指定が必須。** R70 のサブインターフェースは `vrf forwarding WAN` / `vrf forwarding kiosk`
に入っているので、素の `ping 192.168.0.123` はグローバルテーブルに経路が無く失敗する。
（両サブ I/F には `no cdp enable` も入っているので CDP でも辿れない）

### 「テーブルが空だった理由」の完全版

前回の QA では「ホストが黙っているから」と説明したが、より正確には
**VLAN とトランクが無いと誰もホストに到達できなかった**から。
R70 が唯一のゲートウェイで、そこへの道が SW700 の中に存在していなかった。

| 欠けていたもの | 起きること |
|---|---|
| `vlan 100,414` が未作成 | トランクで VLAN 100/414 が通らない |
| Gi2/1 がトランクでない | dot1q タグが落ちて R70 のサブ I/F に届かない |
| Gi0/0 が access vlan 100 でない | ホストのフレームが VLAN 1 に入ってしまう |

**この 3 つが揃って初めて R70 ↔ host71 が疎通し、トラフィックが流れ、SW700 が学習する。**
設定を全部終えた時点でテーブルが埋まったのは、そこで初めて「道」が開通したから。

---

### 推奨手順（Task 1.13 の正しい順番）

#### Step 1 — まず L2 の道を作る（port-security はまだ入れない）

```
vlan 100,414
!
interface GigabitEthernet2/1
 switchport trunk encapsulation dot1q
 switchport mode trunk
!
interface GigabitEthernet0/0
 switchport mode access
 switchport access vlan 100
!
interface GigabitEthernet0/1
 switchport mode access
 switchport access vlan 414
```

#### Step 2 — 疎通させて MAC を出す

```
R70#   ping vrf WAN 192.168.0.123
R70#   ping vrf kiosk 172.31.70.123
SW700# show mac address-table interface GigabitEthernet0/0
SW700# show mac address-table interface GigabitEthernet0/1
```

うまくいかなければ Step 0 として host 側で `show interfaces Ethernet0/0` を直接読めばよい。

#### Step 3 — MAC を控えてから port-security を入れる

```
interface GigabitEthernet0/0
 switchport port-security
 switchport port-security max 1
 switchport port-security mac-address aabb.cc00.7100    ← Step 2 で得た値
 switchport port-security violation restrict
```

**⚠️ よくあるハマり**: `switchport port-security` を先に有効化すると、既に学習済みの MAC が
「動的セキュア MAC」として 1 枠を占有する。そこへ静的 MAC を追加すると `maximum 1` を超えてエラー:

```
Total secure mac-addresses on interface GigabitEthernet0/0 has reached maximum limit.
```

枠を空けてから入れ直す:

```
SW700# clear port-security dynamic interface GigabitEthernet0/0
```

### 確認

```
SW700# show port-security address
Vlan  Mac Address       Type                 Ports  Remaining Age
100   aabb.cc00.7100    SecureConfigured     Gi0/0        -
414   aabb.cc00.7200    SecureConfigured     Gi0/1        1
```

`Type` が **`SecureConfigured`** なら「スタティックに設定すること」の要件を満たしている。
`SecureDynamic` だと自動学習なので要件未達。
