# Pattern 2 問題4 — HSRP 仮想 IP がデフォルト GW である理由と ip helper-address の役割

## 質問

- vlan 2000,2001において standby 210 ip address で 10.1.100.1 としているが、これは問題文ではデフォルトゲートウェイのIPだ。なぜこれを入れている？
- ip helper-address 10.2.255.211 はなぜ入れている？

## 回答

### Q1. 仮想 IP = デフォルトゲートウェイ IP

「デフォルトゲートウェイ IP だから入れている」が答え。HSRP の仮想 IP とは、ホストがデフォルト
ゲートウェイとして向ける「どちらか生きている方のスイッチが引き受けるアドレス」そのもの。
問題文の表はゴール（ホストから見た GW = 10.1.100.1）を定義し、タスク文「ファーストホップ
ゲートウェイを構成しなさい」がその 10.1.100.1 を 2 台で冗長化しろという指示になっている。

初期コンフィグ（EI_v2.yaml）では `.1` は空いている:

| | Vlan2000 | Vlan2001 |
|---|---|---|
| SW101 実 IP | 10.1.100.**2** | 10.1.101.**2** |
| SW102 実 IP | 10.1.100.**3** | 10.1.101.**3** |
| 仮想 IP（HSRP） | 10.1.100.**1** | 10.1.101.**1** |

`.1` がどちらにも振られていないのは意図的。HSRP の仮想 IP はサブネット内の**未使用アドレス**を
使う（VRRP の IP オーナーのように実 IP を仮想 IP に流用する設計は取らない）。

動作:

1. ホストが 10.1.100.1 に ARP → Active（SW101）が仮想 MAC `0000.0c9f.f0d2` で応答
2. SW101 障害 → SW102 が同じ IP・同じ vMAC を引き継ぐ
3. ホストは ARP キャッシュもデフォルト GW 設定も変更不要で通信継続

- 仮に `10.1.100.2`（SW101 実 IP）にすると SW101 障害時にゲートウェイごと消え、冗長化の意味がない
- 設定しなければ 10.1.100.1 は誰も ARP 応答しないため、DHCP で GW 10.1.100.1 を配られたホストは全滅

**注意**: VLAN2001 はグループ 220（`standby 220 ip 10.1.101.1`）。グループ番号 210/220 は VLAN 番号
由来ではなく、仮想 MAC 要件からの逆算（`0x0D2`=210, `0x0DC`=220）。

### Q2. ip helper-address 10.2.255.211

DHCP サーバが別サブネットにいるため、ブロードキャストを届ける代理人（DHCP リレー）が必要。

10.2.255.211 は EI_v2.yaml 上 **SW211 の Loopback0**（DC 側）。クライアントは HQ の
10.1.100.0/24 / 10.1.101.0/24 にいるので、間に L3 境界がある。

- IP を持たないクライアントは `DHCPDISCOVER` を 255.255.255.255 宛ブロードキャストで送出
- ルータ/SVI はブロードキャストを転送しない → そのままでは DC のサーバに届かない
- `ip helper-address 10.2.255.211` を SVI に入れると、10.2.255.211 宛ユニキャストに変換して転送
- このとき **giaddr に受信 SVI の実 IP**（SW101=10.1.100.2 / SW102=10.1.100.3）が入る
- サーバは giaddr でスコープ 10.1.100.0/24 を選び、アドレスとデフォルト GW 10.1.100.1 を返す

→ **Q1 の 10.1.100.1 をホストに配る仕事をしているのが、この helper-address 経由の DHCP**。
2 つの質問は繋がっている。

**両スイッチの両 SVI に入れる理由**: 問題文「DHCP 要求メッセージが、両方のファーストホップ
ゲートウェイスイッチで受信されるようにすること」への対応。SW101/SW102 は同じ VLAN にいるので
ブロードキャストは物理的には両方に届いているが、実際にリレーするのは helper-address を持つ
機器だけ。両方に入れて初めて「両方で受信（処理）される」状態になる。副次的に HSRP フェイル
オーバー中も DHCP が途切れない。2 台同時リレーになるため、サーバ側でどちらの経路か識別できる
よう `ip dhcp relay information option`（Option 82）と `trust` がセットで必要
（[[2026-08-03_q4_DHCPリレー2行の役割とSW102にdecrementが必要な理由]] 参照）。

**補足**: 10.2.255.211 は `ip sla 1 / icmp-echo 10.2.255.211` の監視先と同じアドレス。
「リレー先に届かなくなったらゲートウェイの役目を降りる」という設計であり、helper-address と
IP SLA トラッキングが同じサーバを向いているのは偶然ではない。
