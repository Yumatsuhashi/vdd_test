# Task 1.9 「クラスフルな状態で広報されないようにすること」を満たすコマンドは？

## 質問

CCIE_train_hub/Questions/pattern2/pattern2_q9.md について

・サービスプロバイダーから学習したルートが、クラスフルな状態で広報されないようにすること。　はどのコマンドが満たしている？

## 回答

**`subnets` キーワード**が該当する。

```
! R11（SP #1 向け CE）
router ospf 1
 redistribute bgp 65001 subnets metric-type 1
                        ^^^^^^^

! R12（別 ISP 向け CE）
router ospf 1
 redistribute connected subnets metric-type 1 route-map CIO
                        ^^^^^^^
```

### なぜ `subnets` なのか

OSPF の `redistribute` は、デフォルトで **「クラスフルなメジャーネットワークに一致する
プレフィックスしか再配布しない」** という古い挙動を持つ。`subnets` を付けないと、
自然マスク（/8・/16・/24）に一致しないサブネット化されたルートは LSA Type 5 が
一切生成されず、黙って捨てられる。

このラボで SP から学習するルートは全てサブネット化されている:

| プレフィックス | 出所 | 自然マスク | `subnets` なしだと |
|---|---|---|---|
| `100.3.11.0/30` | R11 Gi0/0 ↔ R3(PE) | /8（クラスA） | 落ちる |
| `101.22.0.0/30` | R22 WAN 側 | /8（クラスA） | 落ちる |
| `200.99.12.0/30` | R12 Gi0/0 ↔ ISP | /24（クラスC） | 落ちる |

つまり `subnets` を書き忘れると **SP 由来のルートが1本も HQ 内に流れない**。

### 他の要件との対応（1行に複数の答えが同居している）

`redistribute bgp 65001 subnets metric-type 1` の1行が、問題文の複数の箇条書きを
同時に満たしている点に注意。

| 要件 | 満たすコマンド／キーワード |
|---|---|
| BGP を使用しないこと | HQ 内は OSPF へ再配布（HQ 内に iBGP を張らない） |
| HQ 内部リンクの帯域幅が考慮されること | **`metric-type 1`**（E1 = 外部メトリック + 内部 OSPF コスト。コストは帯域幅由来） |
| **クラスフルな状態で広報されないこと** | **`subnets`** |
| R12 の ISP 接続 I/F を OSPF へ再配送 | R12: `redistribute connected subnets metric-type 1 route-map CIO`（`match interface GigabitEthernet0/0` = 200.99.12.2/30 の ISP 側） |
| R11 が R22 の WAN ネットワークを広報しない | `ip prefix-list DENY-R22 deny 101.22.0.0/30` + `distribute-list prefix DENY-R22 out bgp 65001` |
| route-map を使用しないこと | R11 のフィルタを route-map ではなく `distribute-list prefix ... out bgp 65001` で実装（Pattern 1 は逆に route-map 版） |

混同しやすい2つを整理すると:

- `metric-type 1` → **メトリックの計算方法**（帯域幅を効かせる）
- `subnets` → **どのプレフィックスを再配布するか**（クラスフル制限の解除）

### 打たないとどうなるか

`subnets` を省略すると、R11 は BGP から SP のルートを受け取っているのに OSPF の
External LSA を1本も生成しない。`show ip ospf database external` が空になり、
HQ 内の R13/SW101 等から SP 方面へ到達できない。BGP テーブルには乗っているので
「BGP は動いているのに HQ 内から届かない」という切り分けの難しい形で現れる。

### 資料との差異 2 点

1. **プレフィックスの値**: 問題文は `101.2.2.0/30` と書くが、CML ラボの R22 Gi1 は
   実際には `101.22.0.2/30` で、解答資料の prefix-list も `101.22.0.0/30`。
   ラボ上は **`101.22.0.0/30`** が正。
2. **route-map 禁止の徹底度**: Pattern 2 の R12 は `route-map CIO` を使っており、
   「route-map を使用しないこと」と厳密には矛盾する。資料上、route-map を完全排除した
   組み合わせは存在しない（Pattern 1 は R11 側で route-map を使用）。制約は実質
   「R11 のフィルタに route-map を使うな」の意味と読むのが妥当。
   完全排除するなら R12 は `redistribute connected subnets metric-type 1` +
   `distribute-list prefix <ISP用> out connected` で代替可能だが、これは資料にはない分析。
