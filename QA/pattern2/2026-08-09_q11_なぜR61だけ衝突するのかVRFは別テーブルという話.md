# Task 1.11 「R61 だけ同じグローバル RIB に持つ」の意味（EIGRP は SP には無い／VRF＝別のルーティングテーブル）

## 質問

もっとわかりやすく教えて R61 だけが、MPLS VPN から学習した経路と DMVPN/EIGRP の経路を同じグローバル RIB に持つ。とありますがそもそもSP内で内でeigrpが設定されていないよね
表を作ってくれたところ全く意味がわからないから解説して

## 回答

### 訂正・整理：EIGRP はどこで動いているか

**EIGRP は SP の中には一切ない。** 指摘の通り。動いているのは **DMVPN トンネルの中だけ**。

```
R24（DC/ハブ）─── Tunnel0 ───┬─── R61（ブランチ3/スポーク）
                              └─── R70（ブランチ4/スポーク）
                     ↑
              ここだけで EIGRP AS 65006 が動く
              （物理的にはインターネットを IPsec で通る）
```

SP #1（AS 10000）の中は OSPF + LDP + MP-BGP。EIGRP とは無関係。
前回の回答の「同じ RIB を持つ」は **SP で EIGRP が動くという意味ではなく、
R61 というルータ1台の中で 2 つの経路源が同じテーブルに入る**という意味だった。

### 問題の本質：R61 には DC へ行く道が「2本」ある

R61 から見て `10.2.114.0/30`（R24 の LAN）へ到達する経路が、**2つの別ルート・別プロトコル**で入ってくる。

```
                          ┌── 道①：MPLS VPN（プライベート・暗号化なし）───┐
                          │   R61 ─ R5(PE) ─ SP内部 ─ R3(PE) ─ R21 ─ DC   │
   10.2.114.0/30 へ ──────┤   使うプロトコル： BGP                          │
   到達するには？          │                                                │
                          └── 道②：DMVPN（インターネット・IPsec 暗号化）──┘
                              R61 ─ インターネット ─ R24
                              使うプロトコル： EIGRP（トンネルの中）
```

**ルータは1つの宛先に1本の経路しか選べない。** どちらを選ぶかは AD で決まる。

| 道 | プロトコル | AD | 勝敗 |
|---|---|---|---|
| ① MPLS VPN | eBGP | **20** | **勝つ** |
| ② DMVPN トンネル | EIGRP internal | 90 | 負ける |

放っておくと **道①（非暗号の MPLS）が選ばれ、DMVPN トンネルが使われない**。
問題文の「トンネル経由で EIGRP で広報」「インターネット通過は全暗号化」に違反する。

→ **道①の入口である R5 で、この3プレフィックスの広報を止める**。これが ACL 66 の役目。

### 表の核心：VRF は「別のルーティングテーブル」

VRF は 1 台のルータの中に**独立したルーティングテーブルをもう1つ作る**機能。
テーブルが違えば、同じプレフィックスが入ってきても**そもそも比較すら起きない**。

#### R61 — 2本の道が「同じ箱」に入る → 衝突する

```
        ┌─────────── R61 のグローバル・ルーティングテーブル ───────────┐
        │                    （箱は1つだけ）                            │
        │   10.2.114.0/30  ← BGP(AD 20)    ★こっちが勝って採用される   │
        │   10.2.114.0/30  ← EIGRP(AD 90)     負けて捨てられる          │
        └───────▲───────────────────────────────────▲──────────────────┘
                │                                   │
          Gi0/0 (VRF なし)                    Tunnel0 (VRF なし)
          100.5.61.2                          10.200.0.61
                │                                   │
             R5 (PE)                            R24 (ハブ)
            MPLS VPN                            DMVPN/IPsec
```

```ios
! R61 初期コンフィグ
interface GigabitEthernet0/0
 ip address 100.5.61.2 255.255.255.252   ← vrf forwarding なし ＝ グローバル
!
router bgp 65006
 neighbor 100.5.61.1 remote-as 10000     ← address-family の外 ＝ グローバル
```

→ **BGP で学んだ経路がグローバル・テーブルに入る。EIGRP 経路も同じ箱。だから衝突する。**

#### R70 — 2本の道が「別の箱」に入る → 衝突しない

```
   ┌── R70 の VRF WAN テーブル ──┐   ┌── R70 のグローバル・テーブル ──┐
   │                              │   │                                │
   │  10.2.114.0/30 ← BGP         │   │  10.2.114.0/30 ← EIGRP         │
   │  （ここに閉じ込められる）     │   │  ★これがそのまま採用される     │
   └──────────▲───────────────────┘   └──────────▲─────────────────────┘
              │                                   │
      Gi0/0.100                               Tunnel0
      vrf forwarding WAN ★                    (VRF なし)
      100.6.70.2                              10.200.0.70
              │                                   │
           R6 (PE)                            R24 (ハブ)
```

```ios
! R70 初期コンフィグ
interface GigabitEthernet0/0.100
 vrf forwarding WAN                      ← ★VRF に隔離されている
 ip address 100.6.70.2 255.255.255.252
!
router bgp 65007
 address-family ipv4 vrf WAN
  neighbor 100.6.70.1 remote-as 10000    ← ★VRF WAN の中
```

→ **BGP 経路は VRF WAN の箱、EIGRP 経路はグローバルの箱。別々なので比較されない。**
→ **R70 は何もしなくても EIGRP 経路が使われる。だから R6 側にフィルタは不要。**

### 混乱しやすいポイント：`tunnel vrf WAN` は「箱」の話ではない

R61/R70 の Tunnel0 に `tunnel vrf WAN` を入れるが、これは
**トンネルの中身のテーブルを VRF にする設定ではない**。

| 設定 | 何を決めるか | 封筒の例え |
|---|---|---|
| `tunnel vrf WAN` | **外側の封筒**（GRE/IPsec の宛先 200.99.24.2）をどのテーブルで配送するか → VRF WAN | 「この手紙はインターネット網の住所録で配達して」 |
| Tunnel0 に `vrf forwarding` **なし** | **中身**（EIGRP で学ぶ 10.2.114.0/30 等）はグローバル・テーブルに入る | 「中に入っていた書類は本社の棚にしまう」 |

だから R61 も R70 も **EIGRP 経路は必ずグローバル**に入る。違うのは BGP 経路の行き先だけ。

（EI_v2.yaml で確認済み: R70 の Tunnel0 は `ip address 10.200.0.70 255.255.255.0` のみで
`vrf forwarding` は無い。R70 で `vrf forwarding WAN` が付くのは Lo0 / Gi0/0.100 / Gi0/2.100、
`vrf forwarding kiosk` が Gi0/2.414）

### 表の読み直し

| CE | 対向 PE | BGP 経路が入る箱 | EIGRP 経路が入る箱 | 同じ箱か | フィルタ要る？ |
|---|---|---|---|---|---|
| **R61** | R5 | **グローバル** | グローバル | **同じ ⚠️** | **要る → R5 に ACL 66** |
| R70 | R6 | VRF WAN | グローバル | 違う ✅ | 不要 |
| R62 | R6 | グローバル | （問題文で「R62 は無視」） | — | 不要（対象外） |

**「同じ箱か」が Yes なのは R61 だけ。だからフィルタは R5 だけ。** これが元の表の趣旨。

R62 も本来は R61 と同じ構造（`router bgp 65006 / neighbor 100.6.62.1 remote-as 10000` がグローバル直下）
なので衝突しうるが、問題文が「このタスクではスポークとしての R62 は無視してください」と明示しているため
R6 側には何も打たない。

### 判定コマンド

R61 で 1 行見れば成否が分かる。

```ios
R61# show ip route 10.2.114.0
D    10.2.114.0/30 [90/...] via 10.200.0.1, Tunnel0     ← ★成功（EIGRP・トンネル経由）
B    10.2.114.0/30 [20/0]  via 100.5.61.1               ← 失敗（BGP・MPLS 経由）
```
