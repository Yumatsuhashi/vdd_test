# Task 1.2 が完了していると「一発」で分かるコマンド

## 質問

task2が完了していると一発でわかるコマンドない？

## 回答

### 結論

- **設定面の一発**: `show interfaces switchport | include Name:|Administrative Mode|Operational Mode|Access Mode VLAN|Trunking VLANs Enabled`
- **機能面の一発（Branch #3 限定・こちらが強い）**: SW601 で `ping 10.6.100.3` と `ping 10.6.101.3`
- **HQ には機能テストの一発が存在しない**（理由は下記）

---

### ① 設定面の一発コマンド（全機器共通）

```
show interfaces switchport | include Name:|Administrative Mode|Operational Mode|Access Mode VLAN|Trunking VLANs Enabled
```

出力（1ポート5行）:

```
Name: Gi0/0
Administrative Mode: static access
Operational Mode: static access
Access Mode VLAN: 2000 (VLAN2000)        ← タグなし要件はここ
Trunking VLANs Enabled: ALL
Name: Gi2/0
Administrative Mode: trunk
Operational Mode: trunk
Access Mode VLAN: 1 (default)
Trunking VLANs Enabled: 1,2000           ← タグあり要件はここ（2001 が無ければ NG）
```

**これが唯一「タグあり・タグなし・リンクダウンポート」の3条件を同時に満たす。**

- 素の `show interfaces switchport` は 1ポート約25行 × 12ポートで読めない。上の5フィールドに絞ると1画面に収まる
- Po1/Po2/Po3 も `Name: Po1` として出るので EtherChannel 側の許可VLANも同時に見える
- **リンクダウンでも `Administrative Mode` は出る**のが決定的に重要（下記）

#### なぜ「リンクダウンでも出る」ことが重要か

`EI_v2.yaml` の links を確認すると、**SW110 Gi0/0・Gi0/1 と SW610 Gi0/0・Gi0/1 にはケーブルが1本も繋がっていない**（links セクションに `SW110-GigabitEthernet0/*` も `SW610-GigabitEthernet0/*` も存在しない）。
要件表の「タグなし」4行はすべてこの未接続ポートなので:

- `show spanning-tree vlan 2000` → STP は up ポートしか載せないので**絶対に出てこない**
- `show interfaces trunk` → そもそもアクセスポートは対象外
- ping → 対向がいないので不可能

つまり**タグなし4行は「設定を読む」以外に検証手段がない**。`show vlan brief` か上記 `show int switchport` を使う。

---

### ② 機能面の一発テスト（Branch #3）

`EI_v2.yaml` の links と SW601 の初期コンフィグから判明した配線:

```
SW601 Gi0/0 ── SW602 Gi0/0    ← no switchport / ip address 10.6.109.1 255.255.255.252（L3 ルーテッドリンク）
SW601 Gi0/1 ── R62 Gi0/2      ← L3
SW601 Gi0/2 ── R61 Gi0/3      ← L3
SW601 Gi2/0 ── SW610 Gi2/0    ← trunk
SW602 Gi2/0 ── SW610 Gi2/1    ← trunk
```

**SW601↔SW602 の直結リンクは L3 ルーテッドポートなので VLAN 2000/2001 は通らない。**
よって Branch #3 における VLAN 2000/2001 の L2 経路は **SW610 経由の1本道**しかない。

SVI の実測値（`EI_v2.yaml`）:

| 機器 | Vlan2000 | Vlan2001 |
|---|---|---|
| SW601 | 10.6.100.2（`standby version 2` / `standby 100`） | 10.6.101.2（`standby 101`） |
| SW602 | 10.6.100.3（`standby 100`） | 10.6.101.3（`standby 0`） |
| SW610 | 10.6.100.10 | **SVI なし** |

**SW601 で打つ:**

```
ping 10.6.100.3     ← VLAN2000
ping 10.6.101.3     ← VLAN2001
```

同一サブネット宛なので L3 ルーティングされず、必ず SVI から L2 で出る。経路は:

```
SW601 Vlan2000 → Gi2/0 (tag 2000) → SW610 Gi2/0 → SW610 内部で L2 スイッチ
                → SW610 Gi2/1 (tag 2000) → SW602 Gi2/0 → SW602 Vlan2000
```

**この2発が通れば、Branch #3 のトランク4ポート × 2VLAN ＝ 要件表8行分が一撃で証明される。**
特に `ping 10.6.101.3` は、SW610 の初期値が `switchport trunk allowed vlan 1,2000`（2001 欠落）のままだと必ず落ちるので、
Task 1.2 最大の罠をピンポイントで炙り出す。

SW610 に Vlan2001 SVI が無くても問題ない（SW610 は L2 スイッチングするだけで、SVI は不要）。

#### ⚠️ HSRP は判定に使わない

SW601/SW602 の HSRP は初期状態で壊れている:

- Vlan2000: SW601 に `standby version 2` があるが SW602 に無い → **バージョン不一致**
- Vlan2001: SW601 が `standby 101`、SW602 が `standby 0` → **グループ番号不一致**

そのため `show standby brief` は L2 が正常でも Active/Active に見える。**実IP同士の ping には一切影響しない**ので、判定は ping で行うこと。
（この HSRP 不整合は Task 1.4 側の論点）

### ③ HQ には機能テストの一発が無い

`EI_v2.yaml` の links:

```
SW110 Gi1/0 ── SW101 Gi1/2   ┐ SW110 Po1 ⇔ SW101 Po1
SW110 Gi1/1 ── SW101 Gi1/3   ┘
SW110 Gi1/2 ── SW102 Gi1/2   ┐ SW110 Po2 ⇔ SW102 Po2
SW110 Gi1/3 ── SW102 Gi1/3   ┘
SW101 Gi2/0 ── SW102 Gi2/0   ┐ SW101 Po3 ⇔ SW102 Po3（直結！）
SW101 Gi2/1 ── SW102 Gi2/1   ┘
```

- SW101 Vlan2000 = 10.1.100.2、SW102 Vlan2000 = 10.1.100.3
- しかし **SW101 と SW102 は Po3 で直結**しているため、`ping 10.1.100.3` は Po3 を通ってしまい **Po1/Po2/SW110 を1ミリも検証しない**
- SW110 は SVI を持たない純 L2 スイッチなので、ping の宛先にもできない

→ **HQ（SW101 / SW102 / SW110）は ① の設定確認コマンドで見るしかない。**
（どうしても機能で見たいなら Po3 を一時 `shutdown` して ping する方法はあるが、本番ではリスクが高いので非推奨）

---

### なぜ他のコマンドでは一発にならないか

| コマンド | タグなし要件 | タグあり要件 | リンクダウンポート |
|---|---|---|---|
| `show vlan brief` | ✓ | **✗ 原理的に不可**（トランクは載らない） | ✓ |
| `show interfaces status` | ✓ | △ `trunk` とは分かるが許可VLAN不明 | ✓ |
| `show interfaces trunk` | ✗ | ✓ | ✗ `not-trunking` になり載らない |
| `show spanning-tree vlan 2000-2001` | ✓ | ✓ | **✗ STP は up ポートのみ** |
| **`show int switchport \| include …`** | **✓** | **✓** | **✓** |

`show spanning-tree vlan 2000-2001`（範囲指定可）はアクセス・トランク両方を FWD/BLK 付きで一覧でき強力だが、
本ラボでは肝心のタグなし4ポートが未接続なので一発コマンドにはなれない。
逆に「トランクが実際に転送しているか」を見るには最強なので、ping が落ちた時の切り分けに使う。

### 実行順（推奨）

1. **SW601**: `ping 10.6.100.3` → `ping 10.6.101.3`（Branch #3 を2発で判定）
2. 落ちたら **SW610**: ① のコマンドで Gi2/0・Gi2/1 の `Trunking VLANs Enabled` に 2001 があるか
3. **SW110 / SW101 / SW102**: ① のコマンド（HQ はこれのみ）
4. **SW110** は追加で `show etherchannel summary`（Po1/Po2 が `SU`、メンバーが `(P)` か）
